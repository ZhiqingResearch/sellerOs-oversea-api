# 支付订单同步飞书

Stripe / 通联订单结算事务提交后，异步写入另一组织的多维表格。仅同步 `SETTLED` 且 `amountCny > 0` 的订单，不影响支付回调、积分入账或收据。

## 配置

在部署环境填写下列四项并重启服务；全部留空表示关闭，部分填写会在启动校验时报错。配置模板见 `.env.example`。

```dotenv
FEISHU_BILLING_APP_ID=""
FEISHU_BILLING_APP_SECRET=""
FEISHU_BILLING_APP_TOKEN=""
FEISHU_BILLING_TABLE_ID=""
```

使用新组织的自建应用，并为应用开通目标多维表格的读取、添加记录权限和文档访问权限。鉴权和 Token 缓存独立于现有 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 店铺同步，不需要影刀配置。`APP_TOKEN` 为多维表格标识，`TABLE_ID` 为目标数据表标识，不需要视图 ID。

## 目标表字段

先在飞书建好以下列，名称需完全一致：

| 字段名             | 类型             | 内容                                                             |
| ------------------ | ---------------- | ---------------------------------------------------------------- |
| 订单号             | 文本             | `BillingOrder.orderNo`，查重依据                                 |
| 用户ID             | 数字             | 付款用户 ID                                                      |
| 用户名             | 文本             | 同步开始时的用户名                                               |
| 手机号             | 数字             | 同步开始时的手机号，以数字写入                                   |
| 邮箱               | Email            | 直接传用户邮箱字符串，由飞书处理点击发邮件；无值留空             |
| 订单类型           | 文本             | 原始枚举，如 `PACK`、`PLAN_NEW`                                  |
| 支付渠道           | 文本             | 原始枚举，如 `WECHAT`、`ALIPAY`、`CARD`                          |
| 订单金额\_人民币元 | 数字             | `amountCny`                                                      |
| 实收金额\_美元     | 数字             | Stripe 的 `amountUsdCents / 100`；通联留空                       |
| 订单状态           | 文本             | `SETTLED`                                                        |
| 支付时间           | 日期（包含时间） | `paidAt` 原始毫秒时间戳，核对表格显示为北京时间，不额外加 8 小时 |

## 重试及边界

- 首次同步失败后，分别等待 1 秒、5 秒、30 秒重试，共最多请求四轮。每轮先按订单号精确查重，再决定是否新增。
- 同一进程串行同步，重复调用同一待同步订单会合并；每笔订单的所有重试复用同一份字段快照。
- 新增使用由目标表和订单号生成的固定 `client_token`（UUIDv4 格式），不会因为超时而更换幂等键。查询失败时不新增。
- 已存在的订单直接视为成功，不覆盖飞书里的人工修改。日志带订单号、成功记录 ID 或最终错误，不记录应用密钥。
- 不改表结构、不新增定时任务、不补录历史订单。配置未开启期间的订单也不会在之后自动补录。
- 重试仅保存在进程内：服务重启、部署中断或重试全部失败后，需要人工按订单号核对补写。
- 飞书官方未明确 `client_token` 的有效期；本功能依赖飞书幂等语义处理超时和多实例并发，不提供跨系统无限期严格唯一保证。人工补录也应先按订单号核对。
