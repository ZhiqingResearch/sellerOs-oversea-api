# 智能定价记录开发技术方案（V1）

> 文档状态：已实现；本文保留为实现和后续演进依据。
>
> 适用范围：智能定价工具生成成功后的个人历史记录归档、列表筛选、详情回显和软删除。
>
> 后端项目：NestJS + Prisma + MySQL。
>
> 时间口径：`Asia/Shanghai`。

## 1. 方案结论

智能定价记录采用“不可变结构化快照”方案：前端成功生成完整五步定价报告后，通过一次 `POST` 请求归档；后端保存完整输入和结果，同时提取列表所需摘要字段。查看历史记录时只读取数据库，不重新调用采购链接解析、竞品分析、AI 模型，也不重新生成报告。

本方案按以下业务口径设计：

1. 定价结果由前端现有定价流程生成。
2. 后端负责身份隔离、DTO 校验、结构校验、快照归档和摘要提取。
3. 后端本期不重复实现定价公式，不重算 `P_floor/P_target/rec/recNet/recMargin`。
4. 定价记录创建后不可编辑；重新生成定价应创建一条新记录。
5. 本期只允许用户查看和删除自己的记录，不提供管理员全量查询。
6. 本期只使用 `JwtAuthGuard`，不接入 `PermissionsGuard`，不增加权限种子。
7. 当前所有定价金额统一按 `USD` 保存，不能根据站点自动推导为 GBP、EUR 或 MXN。
8. 不保存报告 HTML，只保存结构化 JSON。

## 2. 本期范围

### 2.1 本期实现

- 成功生成定价报告后创建记录。
- 基于 `clientRequestId` 的创建幂等。
- 用户维度的数据隔离。
- 按产品名、站点名称、类目搜索。
- 按站点代码、类目、北京时间日期范围筛选。
- 按创建时间倒序分页。
- 获取完整产品、输入、竞品上下文和定价结果快照。
- 软删除当前用户的记录。
- 来源 URL 脱敏和清理。
- 请求快照大小限制。
- Swagger 接口示例、单元测试和构建验证。

### 2.2 本期不实现

- 不实现定价生成接口。
- 不在后端重复实现或校验完整定价公式。
- 不重新调用链接解析、竞品分析或大模型。
- 不提供记录编辑接口。
- 不提供恢复软删除接口。
- 不提供管理员查看全部用户记录接口。

- 不实现多币种、汇率转换和汇率历史。
- 不增加 `tool.smart_pricing` 或其他权限配置。
- 不迁移其他模块中的历史报告数据。

## 4. 核心数据契约

### 4.1 站点

当前支持以下站点：

```ts
export const SMART_PRICING_MARKETPLACES = {
  AMAZON_US: "Amazon US",
  WALMART_US: "Walmart US",
  AMAZON_UK: "Amazon UK",
  AMAZON_DE: "Amazon DE",
  TIKTOK_MX: "TikTok MX",
} as const

export type SmartPricingMarketplaceCode = keyof typeof SMART_PRICING_MARKETPLACES
```

请求同时携带稳定代码和展示名称：

```ts
marketplaceCode: SmartPricingMarketplaceCode
marketplaceName: (typeof SMART_PRICING_MARKETPLACES)[SmartPricingMarketplaceCode]
```

后端必须校验 code/name 是否匹配，不能只分别校验两个字符串是否属于合法集合。

数据库字段使用 `VARCHAR`，不使用 MySQL Enum。增加新站点时需要更新应用常量和 DTO 校验，但不需要修改数据库字段类型。

### 4.2 币种

本期请求必须显式传：

```ts
currency: "USD"
```

后端不根据站点自动推导币种。即使站点是 Amazon UK、Amazon DE 或 TikTok MX，当前报告中的金额仍按 USD 快照保存。

未来支持当地币种时，需要升级 `schemaVersion`，并同时定义成本币种、竞品币种、汇率、换算时间和展示符号，不能只放开 `currency` 校验。

### 4.3 数值单位

| 字段 | 单位约定 |
| --- | --- |
| `cost/freight/fba/Cfix/P_floor/P_target/P_ceiling/rec/recNet` | `currency` 指定的金额 |
| `commR/acosR/retR/vatR/premium/targetM/rateSum` | 小数；`0.18` 表示 18% |
| `recMargin` | 百分数；`16.7113` 表示 16.7113% |
| `sHealth/sCompete/sConv/sRisk/composite` | 0～100 的评分 |

列表接口原样返回 `netMargin=16.7113`，前端显示时格式化为 `16.7%`，不能再次乘以 100。

## 5. Prisma 数据模型

```prisma
model SmartPricingRecord {
  /// 定价记录 ID，UUID v4 格式
  id                String   @id @default(uuid()) @db.VarChar(36)
  /// 所属用户，从 JWT 获取
  userId            Int
  user              User     @relation(fields: [userId], references: [id])
  /// 前端创建请求 ID，用于创建幂等
  clientRequestId   String   @db.VarChar(64)
  /// 规范化创建内容的 SHA-256 指纹
  createFingerprint String   @db.VarChar(64)

  /// 当前快照结构版本
  schemaVersion     Int      @default(1)
  /// 唯一且稳定的站点代码，例如 AMAZON_US
  marketplaceCode   String   @db.VarChar(32)
  /// 归档时的站点展示名称，例如 Amazon US
  marketplaceName   String   @db.VarChar(64)
  /// 当前固定为 USD
  currency          String   @db.Char(3)
  category          String   @db.VarChar(255)

  /// 列表摘要字段，由后端从 JSON 快照提取
  productName       String   @db.VarChar(500)
  suggestedPrice    Decimal  @db.Decimal(18, 6)
  netMargin         Decimal  @db.Decimal(12, 6)
  netProfit         Decimal  @db.Decimal(18, 6)
  floorPrice        Decimal  @db.Decimal(18, 6)
  compositeScore    Decimal  @db.Decimal(7, 4)
  verdictText       String   @db.VarChar(255)

  /// 完整不可变快照
  product           Json
  inputSnapshot     Json
  competitorContext Json?
  result            Json

  /// 当前创建版本固定从 1 开始；保留给未来演进
  version           Int      @default(1)
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt
  deletedAt         DateTime?

  @@unique([userId, clientRequestId])
  @@index([userId, deletedAt, createdAt])
  @@index([userId, marketplaceCode, deletedAt, createdAt], map: "SmartPricingRecord_user_market_created_idx")
  @@index([userId, category, deletedAt, createdAt], map: "SmartPricingRecord_user_category_created_idx")
}
```

`User` 增加反向关系：

```prisma
smartPricingRecords SmartPricingRecord[]
```

### 5.1 字段设计说明

- 完整报告只用于详情回显，保存为 JSON 快照。
- 列表字段单独结构化保存，列表查询不读取三个大 JSON。
- 摘要字段只能由后端从经过校验的 `product/result` 提取，前端不单独提交摘要，避免两套数据不一致。
- `netProfit/netMargin` 允许为负数，以支持不可行或亏损方案。
- 价格、保本价不能为负数。
- `compositeScore` 必须在 0～100 之间。
- 金额摘要使用六位小数，详情中的原始 JSON 数值保持前端提交精度。

### 5.2 Migration 约束

Prisma Schema 不能表达的约束写入 migration SQL：

```sql
ALTER TABLE `SmartPricingRecord`
  ADD CONSTRAINT `chk_smart_pricing_schema_version`
    CHECK (`schemaVersion` >= 1),
  ADD CONSTRAINT `chk_smart_pricing_version`
    CHECK (`version` >= 1),
  ADD CONSTRAINT `chk_smart_pricing_suggested_price`
    CHECK (`suggestedPrice` >= 0),
  ADD CONSTRAINT `chk_smart_pricing_floor_price`
    CHECK (`floorPrice` >= 0),
  ADD CONSTRAINT `chk_smart_pricing_composite_score`
    CHECK (`compositeScore` BETWEEN 0 AND 100);
```

`userId` 外键使用 `ON DELETE RESTRICT ON UPDATE CASCADE`，与当前项目其他用户资源一致。

### 5.3 软删除

`SmartPricingRecord` 必须加入 `src/prisma/prisma.service.ts` 的 `SOFT_DELETE_MODELS`。普通读取会自动追加 `deletedAt: null`。

唯一键不会因软删除释放。记录删除后，原 `clientRequestId` 不允许再次创建；前端重新生成报告时必须创建新的 UUID。

事务和唯一冲突处理不能依赖软删除扩展自动生效，需要显式处理 `deletedAt`，必要时使用参数化 `$queryRaw` 查询包含已删除的数据。

### 6.2 分页查询

```http
GET /api/smart-pricing/records?page=1&pageSize=10&keyword=Example&marketplaceCode=AMAZON_US&category=家居厨房&dateFrom=2026-08-01&dateTo=2026-08-25
```

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `page` | 否 | 默认 1，最小 1 |
| `pageSize` | 否 | 默认 10，范围 1～100 |
| `keyword` | 否 | 同时匹配产品名、站点展示名、类目，最大 500 字符 |
| `marketplaceCode` | 否 | 站点代码精确筛选 |
| `category` | 否 | 类目精确筛选 |
| `dateFrom` | 否 | `YYYY-MM-DD`，北京时间当天开始，包含 |
| `dateTo` | 否 | `YYYY-MM-DD`，北京时间当天结束，包含该自然日 |

`dateFrom/dateTo` 的数据库条件使用左闭右开区间。例如：

```text
dateFrom=2026-08-25 -> createdAt >= 2026-08-25T00:00:00+08:00
dateTo=2026-08-25   -> createdAt <  2026-08-26T00:00:00+08:00
```

“近 7 天”定义为包含今天在内连续 7 个北京时间自然日，前端应传今天和前 6 天。

`marketplaceCode/category/date` 与 `keyword` 之间是 AND；`keyword` 内部三个字段之间是 OR。

排序固定为：

```ts
orderBy: [{ createdAt: "desc" }, { id: "desc" }]
```

### 6.4 删除记录

```http
DELETE /api/smart-pricing/records/:recordId
```

服务层使用：

```ts
await prisma.smartPricingRecord.updateMany({
  where: { id: recordId, userId, deletedAt: null },
  data: { deletedAt: new Date(), version: { increment: 1 } },
})
```

- 删除成功返回 HTTP 204，无响应体。
- 记录不存在、属于其他用户或已经删除，统一返回 404。
- 不泄露其他用户是否拥有指定 UUID。

## 7. 创建校验与规范化

### 7.1 DTO 基础校验

| 字段 | 规则 |
| --- | --- |
| `clientRequestId` | UUID v4 |
| `schemaVersion` | 本期只接受整数 1 |
| `marketplaceCode` | 当前支持代码之一 |
| `marketplaceName` | 非空且必须与 code 映射一致 |
| `currency` | 必须严格等于 `USD` |
| `category` | trim 后非空，最大 255 字符 |
| `product.name` | trim 后非空，最大 500 字符 |
| `sourceText` | 可选，最大 4000 字符 |
| `sourceUrl` | 可选，有值时必须是 HTTP(S) URL，最大 2048 字符 |
| `filenames` | 可选，最多 20 个，每个最大 255 字符 |
| `extractedProductInfo` | 可选，最大 4000 字符 |
| `competitors` | 最多 100 项 |
| 完整快照 | UTF-8 JSON 最大 1 MiB |

所有 number 必须满足：

- `typeof value === "number"`；
- `Number.isFinite(value)`；
- 禁止 NaN 和 Infinity。

输入成本和价格不得为负数。输入费率 `commR/acosR/retR/vatR/premium/targetM` 本期限制在 `[0, 1]`。

`recNet/recMargin` 允许为负；价格字段、竞品价格、阶段价格和瀑布金额不得为负。

### 7.2 Result 结构校验

- `result.name` 必须与规范化后的 `product.name` 一致。
- `result` 中重复的 `cost/freight/fba/commR/acosR/retR/vatR/premium/targetM` 必须与 `input` 一致；number 比较使用很小的容差，避免浮点表达差异。
- 本期不校验 `Cfix/rateSum/P_floor/P_target/P_ceiling/rec/recNet/recMargin` 的计算公式。
- 四个子评分和综合评分必须在 0～100 之间。
- `verdict.t` trim 后非空，最大 255 字符。
- `verdict.c` 必须匹配 `^#[0-9a-fA-F]{6}$`。
- `competitorRecommendation` 可选，最大 2000 字符。
- `stages` 必须正好 4 项。
- 每个 stage 必须是长度为 4 的 tuple：三个非空字符串和一个非负有限价格。
- `stageName` 最大 100 字符，`objective` 最大 500 字符，`strategy` 最大 2000 字符。
- `waterfall` 在 `input.vatR === 0` 时必须 4 项，在 `input.vatR > 0` 时必须 5 项。
- 每个 waterfall item 必须是长度为 3 的 tuple：非空 label、非负有限 amount、HEX color。
- 不固定校验阶段名称、策略内容、瀑布标签或颜色具体值，避免展示文案调整导致接口不兼容。

### 7.3 竞品上下文校验

`competitorContext` 可以为 `null`。非空时：

- `sampleSize` 是非负整数。
- `competitors` 最多 100 项。
- `sampleSize >= competitors.length`，允许样本总数大于实际归档的明细数。
- `priceMin/priceMedian/priceMax` 是非负有限数。
- 满足 `priceMin <= priceMedian <= priceMax`。
- `title` 非空，最大 1000 字符。
- `asin` 可选；有值时 trim、转大写，并符合 10 位字母数字格式。
- `brand` 可选，最大 255 字符。
- `rating` 可选，范围 0～5。
- `ratings` 可选，必须为非负整数。

竞品查询失败时前端传 `null`，不影响记录保存。

### 7.4 URL 清理

`sourceUrl` 有值时：

1. 使用标准 `URL` 解析。
2. 只接受 `http:` 和 `https:`。
3. 只保存 `origin + pathname`。
4. 丢弃 username/password、query 和 hash。

例如：

```text
输入：https://www.1688.com/offer/123.html?spm=abc#detail
保存：https://www.1688.com/offer/123.html
```

如果 `sourceText` 本身能够完整解析为 HTTP(S) URL，也执行相同清理；否则按普通文本 trim 后保存。

`filenames` 只接受文件名，包含 `/`、`\` 或 NUL 字符时拒绝，不接受浏览器本地路径。

### 7.5 快照大小

大小计算对象包含：

```ts
{
  schemaVersion,
  marketplaceCode,
  marketplaceName,
  currency,
  category,
  product,
  input,
  competitorContext,
  result,
}
```

使用：

```ts
Buffer.byteLength(JSON.stringify(snapshot), "utf8")
```

最大值暂定 `1 * 1024 * 1024` 字节。超过时返回 HTTP 413 和 `SMART_PRICING_RECORD_PAYLOAD_TOO_LARGE`。当前全局 JSON body 上限是 5 MB，因此正常情况下业务层能先给出明确错误码。

## 8. 创建幂等与并发

### 8.1 指纹内容

先完成所有 trim、站点映射校验、ASIN 标准化和 URL 清理，再对以下内容生成稳定 SHA-256：

```ts
hashJson({
  schemaVersion,
  marketplaceCode,
  marketplaceName,
  currency,
  category,
  product,
  input,
  competitorContext,
  result,
})
```

`clientRequestId` 和 `userId` 不进入指纹；它们用于定位幂等记录。

稳定 JSON 规则：对象键排序，数组保持业务顺序，数字必须有限。

### 8.2 行为规则

| 情况 | 处理 |
| --- | --- |
| 首次请求 | 创建记录，`idempotentReplay=false` |
| 相同用户、相同 ID、相同指纹 | 返回原记录，`idempotentReplay=true` |
| 相同用户、相同 ID、不同指纹 | 409 `CLIENT_REQUEST_ID_REUSED` |
| 不同用户使用相同 ID | 各自允许创建，不冲突 |
| 原记录已经软删除 | 409 `SMART_PRICING_RECORD_ALREADY_DELETED` |
| 两个相同请求并发创建 | 一个成功；另一个捕获 P2002 后按指纹返回幂等结果 |

流程：

1. 先按 `(userId, clientRequestId)` 查询未删除记录。
2. 存在则比较指纹并返回幂等结果或 409。
3. 不存在则执行 create。
4. 捕获 Prisma `P2002`。
5. 使用包含软删除行的参数化查询重新读取唯一键记录。
6. 根据 `deletedAt/createFingerprint` 返回幂等、已删除或误复用错误。

整个流程不能使用“先 count 再 create”作为唯一并发保证，数据库唯一索引是最终兜底。

## 9. 时间和查询实现

日期参数只接受严格的 `YYYY-MM-DD`，不能依赖服务器本地时区隐式解析。

北京时间没有夏令时，本期可以明确生成 `+08:00` 边界：

```ts
const from = new Date(`${dateFrom}T00:00:00+08:00`)
const toExclusive = new Date(`${nextCalendarDate(dateTo)}T00:00:00+08:00`)
```

必须按日历日期计算 `nextCalendarDate`，不要在本地时区 Date 上调用 `setDate`。同时校验：

- 日期真实存在，例如拒绝 `2026-02-30`。
- `dateFrom <= dateTo`。

Prisma where 结构：

```ts
const where: Prisma.SmartPricingRecordWhereInput = {
  userId,
  ...(marketplaceCode && { marketplaceCode }),
  ...(category && { category: category.trim() }),
  ...((from || toExclusive) && {
    createdAt: {
      ...(from && { gte: from }),
      ...(toExclusive && { lt: toExclusive }),
    },
  }),
  ...(keyword && {
    OR: [
      { productName: { contains: keyword } },
      { marketplaceName: { contains: keyword } },
      { category: { contains: keyword } },
    ],
  }),
}
```

数据库使用当前 utf8mb4 Unicode collation，keyword 匹配按数据库 collation 的大小写规则执行。

## 10. 响应映射

Prisma Decimal 不直接泄露到接口契约。列表响应显式转换：

```ts
suggestedPrice: record.suggestedPrice.toNumber()
netMargin: record.netMargin.toNumber()
netProfit: record.netProfit.toNumber()
floorPrice: record.floorPrice.toNumber()
compositeScore: record.compositeScore.toNumber()
```

详情中的 `product/inputSnapshot/competitorContext/result` 是 JSON 原始快照，直接按 API 字段名映射，不从摘要列重建报告。

## 11. 错误处理

业务错误：

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | `INVALID_SMART_PRICING_RECORD` | 站点映射、Result tuple、跨字段一致性等业务校验失败 |
| 400 | `INVALID_DATE_RANGE` | 日期非法或起止倒置 |
| 404 | `SMART_PRICING_RECORD_NOT_FOUND` | 详情或删除目标不存在、已删除或属于其他用户 |
| 409 | `CLIENT_REQUEST_ID_REUSED` | 同一幂等 ID 被用于不同内容 |
| 409 | `SMART_PRICING_RECORD_ALREADY_DELETED` | 幂等 ID 对应记录已软删除 |
| 413 | `SMART_PRICING_RECORD_PAYLOAD_TOO_LARGE` | 完整快照超过 1 MiB |

业务异常使用对象形式抛出，以便当前全局异常过滤器保留 `code`：

```ts
throw new BadRequestException({
  code: "INVALID_SMART_PRICING_RECORD",
  message: "waterfall 数量与 vatR 不一致",
})
```

DTO 装饰器产生的基础类型错误沿用项目现有 ValidationPipe 响应格式，不强制包装为统一业务 code。

## 12. 安全与日志

- `userId` 只能从 JWT 获取，DTO 不接收 `userId`。
- 列表、详情、删除所有数据库条件都必须包含 `userId`。
- 跨用户访问返回 404，不返回 403。
- 日志只记录 `recordId/userId/payloadBytes/idempotentReplay` 等摘要。
- 日志不得记录完整产品输入、采购链接原文、竞品列表或完整结果 JSON。
- URL 查询参数必须在指纹和入库前清理。
- 颜色只接受 HEX，降低前端直接使用样式值时的注入风险。
- 前端渲染所有文案仍需正常进行 HTML 转义；后端保存 JSON 不代表字符串可信。

## 16. 评审确认项

本文默认采用：**前端负责定价计算，后端只做结构、边界和重复字段一致性校验，不重复实现定价公式。**
