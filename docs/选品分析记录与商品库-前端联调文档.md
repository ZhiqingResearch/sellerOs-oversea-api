# 选品分析记录与商品库前端联调文档

> 对应当前后端实际实现，不是接口草案。
>
> 更新时间：2026-08-21。
>
> 后端全局路由前缀：`/api`。

## 1. 联调范围

本功能包含三组接口：

1. 选品分析记录：`CATALOG` 保存「类目选品」1～5 步结果；`PRODUCT` 一次保存「产品验证」PDF URL 与商品 JSON。
2. PDF 上传：前端申请 Presigned PUT URL，将 PDF 直传对象存储，再将 `publicUrl` 写入产品验证记录。
3. 商品库：保存商品及不同来源分析下的画像，支持分析来源、类目、价格和入库时间筛选。

核心数据关系：

```text
一次选品分析 analysisId
├── CATALOG：步骤1～5
└── PRODUCT：单步最终结果（PDF URL + productData）

商品库商品（同一用户 + 站点 + ASIN 唯一）
└── 来源画像快照（来源分析 + 关键词可多条）
```

## 2. 通用约定

### 2.1 鉴权与权限

调用后端 JSON API 时需要：

```http
Authorization: Bearer <token>
Content-Type: application/json
```

- `userId` 从 Token 获取，前端不要传。
- 分析记录和商品库接口要求 `tool.flow_workbench` 权限；`/api/spaces/upload-url` 只要求有效 JWT。
- 不存在、已软删除或不属于当前用户的资源统一按 `404` 处理。

### 2.2 Base URL

完整路径均以 `/api` 开头，例如：

```text
POST /api/product-selection/analysis-records
```

如果前端 `request()` 已配置 `baseURL=/api`，调用时只传：

```text
/product-selection/analysis-records
```

### 2.3 分页格式

列表接口统一使用：

```text
page     默认 1，最小 1
pageSize 默认 10，范围 1～100
```

统一分页响应：

```ts
interface PageResult<T> {
  items: T[]
  total: number
  page: number
  pageSize: number
  totalPages: number
}
```

### 2.4 错误响应

带业务错误码时：

```json
{
  "statusCode": 409,
  "code": "ANALYSIS_VERSION_CONFLICT",
  "message": "分析记录已在其他页面更新，请刷新后重试",
  "details": {
    "expectedVersion": 3,
    "currentVersion": 4
  },
  "timestamp": "2026-08-20T08:00:00.000Z"
}
```

DTO 基础校验错误可能没有 `code`，`message` 可能是字符串数组：

```json
{
  "statusCode": 400,
  "message": ["schemaVersion must not be greater than 1"],
  "timestamp": "2026-08-20T08:00:00.000Z"
}
```

前端错误类型建议：

```ts
interface ApiErrorBody {
  statusCode: number
  code?: string
  message: string | string[]
  details?: Record<string, unknown>
  timestamp: string
}
```

## 3. 选品分析记录

### 3.1 接口清单

| 方法 | 路径 | 用途 | 成功状态码 |
| --- | --- | --- | --- |
| `POST` | `/api/product-selection/analysis-records` | 创建分析并保存第 1 步 | `201` |
| `PUT` | `/api/product-selection/analysis-records/{analysisId}/steps/{stepNo}` | 仅 `CATALOG`：保存或重新保存第 1～5 步 | `200` |
| `GET` | `/api/product-selection/analysis-records` | 分页查询分析记录 | `200` |
| `GET` | `/api/product-selection/analysis-records/{analysisId}` | 查询详情并恢复所有有效步骤 | `200` |
| `DELETE` | `/api/product-selection/analysis-records/{analysisId}` | 软删除分析记录 | `204` |

`analysisId` 是 UUID v4。`CATALOG` 的 `stepNo` 只能是 `1～5`；`PRODUCT` 不调用步骤保存接口。

### 3.2 TypeScript 公共类型

```ts
type SelectionAnalysisEntry = "CATALOG" | "PRODUCT"
type SelectionAnalysisStatus = "PROCESSING" | "COMPLETED"

type SelectionAnalysisStepType =
  | "CATEGORY_DIAGNOSIS"
  | "TRACK_VALIDATION"
  | "COMPETITOR_POOL"
  | "TRAFFIC_AD_VALIDATION"
  | "PRODUCT_LIST"
  | "PRODUCT_VALIDATION"

interface SelectionCategory {
  nodeId: string
  nodeIdPath: string
  name: string
  nameCn?: string
}

interface AnalysisMutationResult {
  analysisId: string
  stepNo: number
  revision: number
  lastCompletedStep: number
  pickCount: number
  status: SelectionAnalysisStatus
  version: number
  updatedAt: string
}
```

类目选品步骤编号与类型固定映射：

| stepNo | stepType | 页面状态 |
| --- | --- | --- |
| 1 | `CATEGORY_DIAGNOSIS` | `diagnoses` |
| 2 | `TRACK_VALIDATION` | `oppResults`、`selectedKeywords` |
| 3 | `COMPETITOR_POOL` | `compResults`、`selectedAsinsByKeyword` |
| 4 | `TRAFFIC_AD_VALIDATION` | `anaResult` |
| 5 | `PRODUCT_LIST` | `reportData` |

## 4. 创建类目选品并保存第 1 步

### 4.1 请求

```http
POST /api/product-selection/analysis-records
```

```json
{
  "clientRequestId": "0a49d1d3-84e7-43a0-8a68-c24f0ed93d27",
  "marketplace": "US",
  "entry": "CATALOG",
  "primaryCategoryNodeId": "172282",
  "categories": [
    {
      "nodeId": "172282",
      "nodeIdPath": "Automotive:Interior Accessories:Cup Holders",
      "name": "Cup Holders",
      "nameCn": "杯架"
    }
  ],
  "schemaVersion": 1,
  "payload": {
    "diagnosis": []
  }
}
```

字段说明：

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `clientRequestId` | 是 | 前端生成 UUID；同一次创建重试必须复用，新分析必须重新生成 |
| `marketplace` | 是 | 站点代码，后端会 trim 并转大写，最长 16 |
| `entry` | 否 | 本流程传 `CATALOG`，不传时默认 `CATALOG` |
| `primaryCategoryNodeId` | 是 | `CATALOG` 必传，必须存在于 `categories[].nodeId` 中 |
| `categories` | 是 | `CATALOG` 必传，1～50 项，`nodeId` 不能重复 |
| `schemaVersion` | 是 | 当前固定为 `1` |
| `payload.diagnosis` | 是 | 数组，最多 500 项，每项必须为对象 |

### 4.2 响应

```json
{
  "analysisId": "5e10c2ea-f40e-48c7-9074-45388a7bfb2f",
  "stepNo": 1,
  "revision": 1,
  "lastCompletedStep": 1,
  "pickCount": 0,
  "status": "PROCESSING",
  "version": 1,
  "idempotentReplay": false,
  "createdAt": "2026-08-20T08:00:00.000Z",
  "updatedAt": "2026-08-20T08:00:00.000Z"
}
```

前端必须保存：

```text
analysisId
version
```

建议将 `analysisId` 写入 URL：

```text
/product-selection-tools/category?analysisId=5e10c2ea-f40e-48c7-9074-45388a7bfb2f
```

### 4.3 创建幂等规则

- 同一用户、相同 `clientRequestId`、相同请求内容：返回原记录，`idempotentReplay=true`。
- 同一 `clientRequestId` 但内容不同：返回 `409 CLIENT_REQUEST_ID_REUSED`。
- 该 `clientRequestId` 对应的分析已删除：返回 `409 ANALYSIS_ALREADY_DELETED`。
- 网络超时后重试创建请求时，不能生成新的 `clientRequestId`。

### 4.4 产品验证：PDF 上传与单步保存

产品验证不调用后续 `PUT /steps/{stepNo}`。前端先完成 PDF 上传，再一次性创建完整记录。

#### 4.4.1 申请 PDF 上传地址

```http
POST /api/spaces/upload-url
```

```json
{
  "filename": "product-validation-B0GWK1HFXP.pdf",
  "contentType": "application/pdf",
  "keyPrefix": "product-validation/",
  "expiresIn": 3600
}
```

响应：

```json
{
  "uploadUrl": "https://signed-upload.example.com/...",
  "publicUrl": "https://cdn.example.com/product-validation/uuid.pdf",
  "key": "product-validation/uuid.pdf",
  "headers": {
    "x-amz-acl": "public-read",
    "Content-Type": "application/pdf"
  },
  "expiresIn": 3600
}
```

前端必须将响应中的 `headers` 原样带入 PUT：

```ts
interface UploadPolicy {
  uploadUrl: string
  publicUrl: string
  key: string
  headers: Record<string, string>
  expiresIn: number
}

const policy = await request<UploadPolicy>("/spaces/upload-url", {
  method: "POST",
  data: {
    filename: file.name,
    contentType: "application/pdf",
    keyPrefix: "product-validation/",
  },
})

const uploadResponse = await fetch(policy.uploadUrl, {
  method: "PUT",
  headers: policy.headers,
  body: file,
})
if (!uploadResponse.ok) throw new Error("PDF 上传失败")
```

- PUT 直传请求不要携带本系统的 `Authorization` 头。
- 只有 PUT 上传成功后，才能把 `publicUrl` 作为 `pdfUrl` 提交。
- 不要保存有效期较短的 `uploadUrl`。

#### 4.4.2 一次性保存产品验证

```http

```

```json
{
  "clientRequestId": "cd62082f-96f0-480e-9727-bbdf425cf6d8",
  "marketplace": "US",
  "entry": "PRODUCT",
  "schemaVersion": 1,

    "pdfUrl": "https://cdn.example.com/product-validation/uuid.pdf",
```

| 字段 | 要求 |
| --- | --- |
| `payload.pdfUrl` | 必传，有效的 HTTP/HTTPS URL，最长 2048 |
| `payload.productData` | 必传，非空 JSON 对象 |
| `primaryCategoryNodeId/categories` | `PRODUCT` 可选；传入时两者必须一致 |

成功响应：

```json
{
  "analysisId": "5e10c2ea-f40e-48c7-9074-45388a7bfb2f",
  "stepNo": 1,
  "revision": 1,
  "lastCompletedStep": 1,
  "pickCount": 1,
  "status": "COMPLETED",
  "version": 1,
  "idempotentReplay": false,
  "createdAt": "2026-08-21T08:00:00.000Z",
  "updatedAt": "2026-08-21T08:00:00.000Z"
```

```text
entry=PRODUCT
```

## 5. 保存类目选品第 1～5 步

> 本章仅适用于 `entry=CATALOG`。`entry=PRODUCT` 不调用本章接口。

### 5.1 统一请求

```http
PUT /api/product-selection/analysis-records/{analysisId}/steps/{stepNo}
```

```json
{
  "expectedVersion": 1,
  "schemaVersion": 1,
  "payload": {}
}
```

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `expectedVersion` | 是 | 上一次创建、保存或详情响应中的最新 `version` |
| `schemaVersion` | 是 | 当前固定为 `1` |
| `payload` | 是 | 只传当前步骤的完整结果对象 |
| `pickCount` | 第5步必需 | 最终入选商品数量；其他步骤禁止传 |

统一响应：

```json
{
  "analysisId": "5e10c2ea-f40e-48c7-9074-45388a7bfb2f",
  "stepNo": 2,
  "revision": 2,
  "lastCompletedStep": 2,
  "pickCount": 0,
  "status": "PROCESSING",
  "version": 3,
  "changed": true,
  "invalidatedSteps": [3, 4, 5],
  "updatedAt": "2026-08-20T08:05:00.000Z"
}
```

- `changed=true`：内容发生变化，`version/revision` 已增加。
- `changed=false`：与数据库内容相同，是无副作用幂等成功；`version/revision` 不变。
- `invalidatedSteps`：因上游变化被删除的下游步骤号。前端必须清空这些步骤的本地状态。

### 5.2 第 1 步

第 1 步首次保存走创建接口。重新生成第 1 步时走统一 `PUT`：

```json
{
  "expectedVersion": 5,
  "schemaVersion": 1,
  "payload": {
    "diagnosis": []
  }
}
```

`diagnosis` 最多 500 项，每项必须是对象。

### 5.3 第 2 步

```json
{
  "expectedVersion": 1,
  "schemaVersion": 1,
  "payload": {
    "oppResults": [],
    "selectedKeywords": ["cup holder", "car cup holder"]
  }
}
```

校验规则：

- `oppResults` 必须是对象数组，最多 500 项。
- `selectedKeywords` 最多 50 项。
- 关键词不能为空，单个最长 500。
- trim 后忽略大小写不能重复。

### 5.4 第 3 步

```json
{
  "expectedVersion": 2,
  "schemaVersion": 1,
  "payload": {
    "compResults": [],
    "selectedAsinsByKeyword": {
      "cup holder": ["B0GWK1HFXP", "B0ABCDEF12"]
    }
  }
}
```

校验规则：

- `compResults` 必须是对象数组，最多 500 项。
- `selectedAsinsByKeyword` 必须是对象，最多 50 个关键词。
- ASIN 必须为 10 位字母或数字。
- 同一关键词下 ASIN 不能重复。
- 所有关键词的 ASIN 总数最多 500。

### 5.5 第 4 步

```json
{
  "expectedVersion": 3,
  "schemaVersion": 1,
  "payload": {
    "anaResult": {
      "traffic": {},
      "advertising": {}
    }
  }
}
```

`anaResult` 必须是非空对象。

### 5.6 第 5 步

```json
{
  "expectedVersion": 4,
  "schemaVersion": 1,
  "pickCount": 2,
  "payload": {
    "reportData": {
      "items": [
        { "asin": "B0GWK1HFXP" },
        { "asin": "B0ABCDEF12" }
      ]
    }
  }
}
```

校验规则：

- `reportData` 必须是非空对象。
- `pickCount` 必须是 `0～500` 的整数。
- 后端按以下顺序识别第一个存在的商品数组，并校验其长度与 `pickCount` 一致：
  - `items`
  - `products`
  - `selectedProducts`
  - `productList`
- 第 5 步保存成功后：`status=COMPLETED`、`lastCompletedStep=5`。

前端应尽快固定一个最终商品数组字段，推荐使用 `reportData.items`。

### 5.7 步骤顺序和重新生成

默认不允许跳步：

```text
保存第2步前必须存在第1步
保存第3步前必须存在第2步
保存第4步前必须存在第3步
保存第5步前必须存在第4步
```

缺少前一步时返回：

```json
{
  "statusCode": 409,
  "code": "PREVIOUS_STEP_NOT_COMPLETED",
  "message": "请先完成第2步",
  "details": {
    "previousStepNo": 2
  },
  "timestamp": "2026-08-20T08:00:00.000Z"
}
```

重新生成上游步骤且内容实际变化时：

| 保存步骤 | 失效步骤 | 保存后状态 |
| --- | --- | --- |
| 1 | 2、3、4、5 | `lastCompletedStep=1` |
| 2 | 3、4、5 | `lastCompletedStep=2` |
| 3 | 4、5 | `lastCompletedStep=3` |
| 4 | 5 | `lastCompletedStep=4` |
| 5 | 无 | `lastCompletedStep=5`、`COMPLETED` |

上游内容相同时不会删除下游，响应 `changed=false`。

### 5.8 版本冲突

内容发生变化且 `expectedVersion` 不是服务端最新版本时返回：

```text
409 ANALYSIS_VERSION_CONFLICT
```

前端处理：

1. 停止当前分析的后续自动保存。
2. 不要直接用新版本号自动重试旧内容。
3. 提示“记录已在其他页面更新”。
4. 重新请求详情，让用户确认最新数据后再操作。

注意：如果请求内容与数据库完全相同，即使携带旧版本也会安全返回 `changed=false`。

### 5.9 数据大小

- 单步骤 `payload` JSON 序列化后不能超过 4 MiB。
- 超限返回 `413 ANALYSIS_PAYLOAD_TOO_LARGE`。
- 整个 HTTP JSON 请求受应用全局 5 MiB 限制。

## 6. 查询分析记录列表


查询参数：

| 参数 | 说明 |
| --- | --- |

页面恢复时先按 `entry` 分流：

```ts
if (detail.entry === "PRODUCT") {
  const result = detail.steps.find(step => step.stepType === "PRODUCT_VALIDATION")
  renderProductValidation(result?.payload)
} else {
  restoreCatalogSteps(detail)
}
```

`CATALOG` 页面展开规则建议：

```ts
const activeStep = detail.status === "COMPLETED"
  ? 5
  : Math.min(detail.lastCompletedStep + 1, 5)
```

`lastCompletedStep` 表示“有效的最高已完成步骤”，不是“下一步”。

## 8. 删除分析记录


## 9. 类目选品前端保存队列建议

`PRODUCT` 无保存队列。`CATALOG` 同一个 `analysisId` 的保存请求必须串行，避免步骤 2 和步骤 3 无序提交。

```ts
interface AnalysisRuntimeState {
  analysisId: string | null
  version: number
  saving: boolean
  saveError: string | null
}

// 伪代码：请按项目 request() 的真实签名调整
async function saveStep(stepNo: number, payload: Record<string, unknown>, pickCount?: number) {
  const result = await request<AnalysisMutationResult & {
    changed: boolean
    invalidatedSteps: number[]
  }>(`/product-selection/analysis-records/${state.analysisId}/steps/${stepNo}`, {
    method: "PUT",
    body: {
      expectedVersion: state.version,
      schemaVersion: 1,
      payload,
      ...(stepNo === 5 ? { pickCount } : {}),
    },
  })

  state.version = result.version
  clearLocalSteps(result.invalidatedSteps)
  return result
}
```

如果项目 `request()` 使用 `data` 而不是 `body`，只调整请求封装参数，业务 JSON 不变。

建议状态提示：

```text
生成完成，正在保存…
已保存
保存失败，点击重试
记录已在其他页面更新，请刷新
```

## 10. 商品库

### 10.1 接口清单

| 方法 | 路径 | 用途 | 成功状态码 |
| --- | --- | --- | --- |
| `POST` | `/api/product-library/items` | 单个商品入库 | `201` |
| `POST` | `/api/product-library/items/batch` | 批量入库，最多 100 项 | `201` |
| `GET` | `/api/product-library/items` | 分页查询商品库 | `200` |

| `DELETE` | `/api/product-library/items/{id}` | 软删除商品 | `204` |

商品库 `id` 是正整数，不是 UUID。

### 10.2 单个商品入库

```http
POST /api/product-library/items
```

```json
{
  "asin": "B0GWK1HFXP",
  "marketplace": "US",
  "keyword": "cup holder",
  "title": "Car Cup Holder",
  "brand": "Example Brand",
  "imageUrl": "https://example.com/product.jpg",
  "compScore": 6.07,
  "price": 17,
  "monthlySales": 800,
  "ratingNum": 27,
  "sourceAnalysisId": "5e10c2ea-f40e-48c7-9074-45388a7bfb2f",
  "tags": ["重点观察"],
  "notes": "下月重新验证广告成本",
  "profile": {
    "competitor": {},
    "analysis": {},
    "marketValidation": {},
    "recommendReasons": ["自然流量占比高"]
  }
}
```

主要校验：

| 字段 | 规则 |
| --- | --- |
| `asin` | 可选；传入时必须为 10 位字母或数字，后端统一转大写 |
| `marketplace` | 必需，最长 16，后端 trim 并转大写 |
| `keyword` | 必需，最长 500，后端合并连续空白 |
| `imageUrl` | 可选，只接受带协议的 HTTP/HTTPS URL |
| `compScore` | 可选，非负，最多 4 位小数 |
| `price` | 可选，非负，最多 2 位小数 |
| `monthlySales/ratingNum` | 可选，0～2147483647 的整数 |
| `sourceAnalysisId` | 必需，必须是当前用户未删除的分析记录 |
| `tags` | 可选，最多 50 个；trim 后忽略大小写不能重复；单项最长 50 |
| `notes` | 可选，最长 10000 |
| `profile` | 必需，非空对象，最大 2 MiB |

响应：

```json
{
  "id": 11,
  "asin": "B0GWK1HFXP",
  "marketplace": "US",
  "snapshotId": 21,
  "snapshotChanged": true,
  "createdAt": "2026-08-20T08:00:00.000Z",
  "updatedAt": "2026-08-20T08:00:00.000Z"
}
```

`snapshotChanged=false` 表示相同来源、关键词和画像已存在，本次未重写画像。

有 `asin` 时，商品主记录仍按 `当前用户 + marketplace + asin` 幂等更新；未传 `asin` 时无法按 ASIN 判断是否为同一商品，因此每次请求会创建独立的商品主记录，响应中的 `asin` 为 `null`。

### 10.3 批量入库

```http
POST /api/product-library/items/batch
```

```json
{
  "items": [
    {
      "asin": "B0GWK1HFXP",
      "marketplace": "US",
      "keyword": "cup holder",
      "sourceAnalysisId": "5e10c2ea-f40e-48c7-9074-45388a7bfb2f",
      "profile": { "analysis": {} }
    }
  ]
}
```

- `items` 数量为 `1～100`。
- 整批在一个事务中处理，任意一项失败则整批回滚。
- 同一批不能包含相同的 `marketplace + asin + sourceAnalysisId + keyword`。

响应：

```json
{

    {
      "id": 11,
      "asin": "B0GWK1HFXP",
      "marketplace": "US",
      "snapshotId": 21,
      "snapshotChanged": true,
      "createdAt": "2026-08-20T08:00:00.000Z",
      "updatedAt": "2026-08-20T08:00:00.000Z"
    }
  ],
  "count": 1
}
```

第五步勾选多个产品时优先使用批量接口，不要循环调用单个接口。

### 10.4 商品去重和再次入库

- 商品主项按 `当前用户 + marketplace + asin` 唯一。
- 同一商品可以保存多个来源分析或关键词下的画像。
- 再次入库会更新商品标题、品牌、图片和最新画像摘要。
- 再次入库不会覆盖用户已经编辑的 `tags/notes`。
- 软删除商品再次入库时会恢复原商品，并保留原标签备注。

## 11. 业务错误码处理表

| HTTP | code | 前端处理建议 |
| --- | --- | --- |
| 400 | `INVALID_CATEGORIES` | 提示类目重复，阻止创建 |
| 400 | `INVALID_PRIMARY_CATEGORY` | 提示重新选择主类目 |
| 400 | `INVALID_STEP_NO` | 前端代码错误，记录日志 |
| 400 | `INVALID_STEP_PAYLOAD` | 展示服务端 message，检查当前步骤数据 |
| 400 | `PRODUCT_VALIDATION_ALREADY_COMPLETE` | 前端不应再调用步骤保存，直接进入详情回显 |
| 404 | `ANALYSIS_NOT_FOUND` | 提示记录不存在或已删除，退出恢复页 |
| 409 | `CLIENT_REQUEST_ID_REUSED` | 新建分析并生成新的 UUID |
| 409 | `ANALYSIS_ALREADY_DELETED` | 新建分析并生成新的 UUID |
| 409 | `PREVIOUS_STEP_NOT_COMPLETED` | 回到缺失的前一步 |
| 409 | `ANALYSIS_VERSION_CONFLICT` | 停止保存并重新拉取详情 |
| 413 | `ANALYSIS_PAYLOAD_TOO_LARGE` | 减少关键词/竞品数后重新生成 |
| 404 | `SOURCE_ANALYSIS_NOT_FOUND` | 禁止入库，提示来源分析不可用 |
| 404 | `PRODUCT_LIBRARY_ITEM_NOT_FOUND` | 返回商品库列表并刷新 |
| 413 | `PRODUCT_PROFILE_TOO_LARGE` | 精简单个商品画像 |

其余常见状态：

```text
401 Token 缺失或失效 → 重新登录
403 缺少 tool.flow_workbench 权限 → 展示无权限页
500 服务端异常 → 通用错误提示并上报
```

## 12. 推荐前端接入顺序

1. 封装分析记录、PDF 直传和商品库 API 及 TypeScript 类型。
2. `PRODUCT`：完成前端预览 → 生成 PDF → 直传 → 一次创建完整记录。
3. `CATALOG`：第 1 步接创建接口，第 2～5 步接串行保存队列。
4. 处理 `invalidatedSteps`，清理类目选品的本地下游数据。
5. URL 增加 `analysisId`，详情恢复时先按 `entry` 分流。
6. 接两个分页列表和所有可选筛选项。
7. 类目选品第 5 步接商品库批量入库。
8. 接商品库详情、标签备注和软删除。
9. 补上传失败、网络超时重试、版本冲突和页面刷新测试。

## 13. 联调验收清单

- [ ] 相同创建请求超时重试不会产生两条分析。
- [ ] `PRODUCT` PDF 直传成功后一次创建，响应直接为 `COMPLETED`。
