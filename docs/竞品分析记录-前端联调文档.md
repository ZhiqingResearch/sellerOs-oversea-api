# 竞品分析记录前端联调文档

## 1. 功能范围

本模块只负责保存和读取前端已经生成完成的竞品分析结果，不会重新执行分析。

- 一条主记录：分析输入、总体分析结果、最终报告、PDF URL。
- 多个产品：每个产品的完整 `productData`。
- 每个产品任意多个步骤：每一步的完整 `resultData`。
- 记录仅创建人可见。所有接口都从 JWT 识别当前用户，前端不传 `userId`。
- 分析内容创建后不可编辑；只允许回写或覆盖报告 PDF URL。

接口统一前缀：`/api`。

请求头：

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

## 2. 推荐前端调用时序

```text
总体分析完成
  → 各产品逐步分析完成
  → 最终报告生成完成
  → POST 创建完整历史记录
  → 用户点击下载 PDF
  → 前端根据 reportData 生成 PDF
  → 前端调用现有文件上传接口并取得 URL
  → PATCH 回写 reportPdfUrl
```

创建历史记录时必须一次提交完整的主结果、产品、步骤和最终报告。任一阶段还未完成时，不要提交半成品。

## 3. 数据类型

以下 TypeScript 类型可直接作为前端接口模型的基础：

```ts
type Marketplace = "US" | "UK" | "DE" | "JP" | "MX"
type AnalysisMode = "ASIN" | "KEYWORD"
type JsonObject = Record<string, unknown>

interface CompetitorAnalysisInput {
  mode: AnalysisMode
  ownAsin: string | null
  competitorAsins: string[]
  keyword: string | null
  sourceText?: string
}

interface CompetitorAnalysisStep {
  stepCode: string
  stepNo: number
  schemaVersion: 1
  resultData: JsonObject
}

interface CompetitorAnalysisProduct {
  asin: string
  sortOrder: number
  productData: JsonObject
  steps: CompetitorAnalysisStep[]
}

interface CreateCompetitorAnalysisRecordRequest {
  clientRequestId: string
  schemaVersion: 1
  marketplace: Marketplace
  input: CompetitorAnalysisInput
  analysisResult: JsonObject
  products: CompetitorAnalysisProduct[]
  reportData: JsonObject
  // 兼容字段；后端不会保存，也不会用它生成摘要
  summary?: JsonObject
}
```

关键约束：

- `analysisResult`、`productData`、`resultData`、`reportData` 必须直接传 JSON 对象。
- 不要对这些字段执行 `JSON.stringify()`；否则后端收到字符串会返回 400。
- 产品内部字段和步骤类型不设固定模板。前端传入什么业务 JSON，后端就保存什么。
- `steps` 可以是空数组；有多少步传多少步。后端不维护步骤白名单。
- 同一产品内 `stepCode`、`stepNo` 必须唯一；`stepCode` 最大 64 字符。
- 同一次记录内产品 `asin`、`sortOrder` 必须唯一。
- ASIN 会 trim 并转大写，必须是 10 位字母数字。
- `competitorAsins` 为 1～20 项，不能重复，也不能包含 `ownAsin`。
- `KEYWORD` 模式必须传非空 `keyword`；`ASIN` 模式必须传 `keyword: null` 或省略。
- 一条完整记录最大 4 MiB；不要传 Base64、Blob URL、DOM 或 HTML 页面快照。

## 4. 创建历史记录

```http
POST /api/competitor-analysis/records
```

请求示例：

```json
{
  "clientRequestId": "9c82fc0e-f74f-4bb8-9075-223ba56d24aa",
  "schemaVersion": 1,
  "marketplace": "US",
  "input": {
    "mode": "ASIN",
    "ownAsin": "B0AAAA0001",
    "competitorAsins": ["B0BBBB0002", "B0CCCC0003"],
    "keyword": null,
    "sourceText": "前端分析时的原始输入"
  },
  "analysisResult": {
    "overview": {
      "marketOpportunity": "high"
    }
  },
  "products": [
    {
      "asin": "B0AAAA0001",
      "sortOrder": 0,
      "productData": {
        "title": "我方产品",
        "price": 29.99,
        "imageUrl": "https://example.com/product.jpg"
      },
      "steps": [
        {
          "stepCode": "PROFILE",
          "stepNo": 1,
          "schemaVersion": 1,
          "resultData": {
            "strengths": ["重量较轻"]
          }
        },
        {
          "stepCode": "CUSTOM_FRONTEND_STEP",
          "stepNo": 2,
          "schemaVersion": 1,
          "resultData": {
            "score": 8.6
          }
        }
      ]
    },
    {
      "asin": "B0BBBB0002",
      "sortOrder": 1,
      "productData": {
        "title": "竞品 A",
        "price": 35.99
      },
      "steps": []
    }
  ],
  "reportData": {
    "conclusion": "建议继续验证价格带",
    "sections": []
  }
}
```

成功响应：HTTP `201`

```json
{
  "recordId": "48efab82-71c1-4d4e-a626-5bc0ac351e53",
  "version": 1,
  "createdAt": "2026-08-25T08:00:00.000Z",
  "updatedAt": "2026-08-25T08:00:00.000Z",
  "idempotentReplay": false
}
```

### 4.1 幂等重试

前端开始归档前生成一个 UUID v4：

```ts
const clientRequestId = crypto.randomUUID()
```

网络超时或未收到响应时，必须使用同一个 `clientRequestId` 和完全相同的业务内容重试：

- 内容相同：返回原记录，`idempotentReplay: true`。
- 内容不同：返回 409 `CLIENT_REQUEST_ID_REUSED`。
- 原记录已经删除：返回 409 `COMPETITOR_RECORD_ALREADY_DELETED`，需要生成新的 UUID。

建议在请求成功前将 `clientRequestId` 和请求体保存在当前页面状态中，不要每次重试都重新生成 UUID。

## 5. 历史记录列表

```http
GET /api/competitor-analysis/records?page=1&pageSize=10&keyword=B0AAAA0001&marketplace=US&dateFrom=2026-08-01&dateTo=2026-08-25
```

查询参数均可选：

| 参数 | 说明 |
| --- | --- |
| `page` | 默认 1 |
| `pageSize` | 默认 10，最大 100 |
| `keyword` | 匹配我方或任一产品 ASIN，可传完整或部分 ASIN |
| `marketplace` | `US/UK/DE/JP/MX` |
| `dateFrom` | 北京时间开始日期，`YYYY-MM-DD`，包含当天 |
| `dateTo` | 北京时间结束日期，`YYYY-MM-DD`，包含当天 |

响应示例：

```json
{
  "items": [
    {
      "recordId": "48efab82-71c1-4d4e-a626-5bc0ac351e53",
      "marketplace": "US",
      "mode": "ASIN",
      "title": "我方 B0AAAA0001 vs 2 个竞品",
      "ownAsin": "B0AAAA0001",
      "competitorAsins": ["B0BBBB0002", "B0CCCC0003"],
      "keyword": null,
      "productCount": 2,
      "competitorCount": 2,
      "reportPdfUrl": null,
      "version": 1,
      "createdAt": "2026-08-25T08:00:00.000Z",
      "updatedAt": "2026-08-25T08:00:00.000Z"
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 10,
  "totalPages": 1
}
```

列表不会返回大 JSON。用户点击某条记录后，再调用详情接口。


响应示例：

```json
{

  "schemaVersion": 1,
  "version": 1,

  },
  "summary": {
    "title": "我方 B0AAAA0001 vs 2 个竞品",
    "ownAsin": "B0AAAA0001",
    "competitorAsins": ["B0BBBB0002", "B0CCCC0003"],
    "productCount": 2,
    "competitorCount": 2
  },
  "analysisResult": {},
  "products": [
    {
      "productId": 11,
      "asin": "B0AAAA0001",
      "sortOrder": 0,
      "productData": {},
      "steps": [
        {
          "stepCode": "PROFILE",
          "stepNo": 1,
          "schemaVersion": 1,
          "resultData": {}
        }
      ]
    }
  ],
  "reportData": {},
  "reportPdfUrl": null,
  "reportPdfUpdatedAt": null,
  "createdAt": "2026-08-25T08:00:00.000Z",
  "updatedAt": "2026-08-25T08:00:00.000Z"

```

产品已按 `sortOrder` 升序返回，步骤已按 `stepNo` 升序返回。历史页面应直接使用服务端顺序，不要依赖对象键顺序。

不存在、已删除或记录属于其他用户时，统一返回 404，不会暴露记录是否存在。

## 7. PDF URL 回写

### 7.1 职责边界

竞品分析模块不负责上传文件，也不提供或调用 PDF 上传接口。前端完成以下操作：

1. 根据 `reportData` 生成 PDF 文件。
2. 调用项目现有的文件上传接口。
3. 从上传接口响应中取得文件 URL。
4. 调用竞品分析记录接口回写该 URL。

文件上传接口的地址、请求格式和响应字段以现有上传模块为准，不属于本文接口契约。不要把 PDF Base64、Blob 或文件二进制提交给竞品分析记录接口。

### 7.2 回写 URL

```http
PATCH /api/competitor-analysis/records/:recordId/report-pdf
```

```json
{
  "reportPdfUrl": "https://cdn.example.com/competitor-analysis/48efab82/report.pdf"
}
```

响应示例：

```json
{
  "recordId": "48efab82-71c1-4d4e-a626-5bc0ac351e53",
  "reportPdfUrl": "https://cdn.example.com/competitor-analysis/48efab82/report.pdf",
  "reportPdfUpdatedAt": "2026-08-25T08:05:00.000Z",
  "version": 2,
  "updatedAt": "2026-08-25T08:05:00.000Z",
  "changed": true
}
```

- URL 必须是上传接口返回的 HTTPS 地址，最大 2048 字符。
- 相同 URL 重复提交成功，`changed: false`，版本号不增加。
- 重新生成 PDF 后可以提交新 URL，旧值会被覆盖，版本号增加。
- PATCH 失败时不要重新上传 PDF，可直接用已经得到的同一 URL 重试 PATCH。

## 8. 删除历史记录

```http
DELETE /api/competitor-analysis/records/:recordId
```

成功返回 HTTP `204`，无响应体。删除后该记录的主结果、产品、步骤和报告都不能再通过 API 获取。

## 9. 错误处理

业务错误响应格式：

```json
{
  "statusCode": 400,
  "code": "INVALID_COMPETITOR_RECORD_PAYLOAD",
  "message": "products 的 asin 不能重复",
  "timestamp": "2026-08-25T08:00:00.000Z"
}
```

| HTTP | code | 前端处理建议 |
| --- | --- | --- |
| 400 | `INVALID_COMPETITOR_RECORD_PAYLOAD` | 展示 `message`，修正请求结构 |
| 400 | `UNSUPPORTED_COMPETITOR_RECORD_SCHEMA_VERSION` | 阻止提交并提示刷新/升级页面 |
| 400 | `INVALID_DATE_RANGE` | 修正日期区间 |
| 400 | `INVALID_REPORT_PDF_URL` | 检查是否传入文件上传接口返回的 HTTPS URL |
| 401 | 无固定业务 code | 进入统一登录失效流程 |
| 404 | `COMPETITOR_RECORD_NOT_FOUND` | 返回历史列表并刷新当前列表 |
| 409 | `CLIENT_REQUEST_ID_REUSED` | 同一次提交被错误地改了内容；生成新 UUID 后重新归档 |
| 409 | `COMPETITOR_RECORD_ALREADY_DELETED` | 生成新 UUID 后重新归档 |
| 413 | `COMPETITOR_RECORD_PAYLOAD_TOO_LARGE` | 移除大文本/Base64/重复数据后重试 |

## 10. 联调验收清单

- 正常保存总体结果、多个产品和每个产品不同数量的步骤。
- 产品 `steps: []` 可以正常保存和回显。
- 自定义步骤代码和自定义 JSON 字段可以原样回显。
- 相同 `clientRequestId`、相同内容重试返回同一 `recordId`。
- 相同 `clientRequestId`、不同内容返回 409。
- 列表分页、ASIN、站点和北京时间日期筛选正确。
- 详情的产品和步骤顺序正确，JSON 字段不是字符串。
- 前端成功生成 PDF、调用现有文件上传接口、回写返回的 URL 并下载。
- 同一 PDF URL 重试不增加版本，新的 PDF URL 可以覆盖。
- A 用户不能查看、修改 PDF URL 或删除 B 用户的记录。
- 删除后列表和详情都不可见。
