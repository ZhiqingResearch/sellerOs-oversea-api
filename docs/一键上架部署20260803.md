## 1. 部署结果

部署完成后应同时可用：

- 仅生产环境执行指定飞书视图的每日店铺同步。
- 店铺、店铺分类、分类永久模板 URL 查询。

## 7. 定时任务核对

| 时间         | 任务                                          | 检查表                               |
| ------------ | --------------------------------------------- | ------------------------------------ |
| 每天 `02:10` | 仅 `prod`：飞书店铺同步；其他环境跳过         | `ProductPublishFeishuSyncRun/Record` |
| 每天 `03:10` | 仅 `prod`：主动请求店铺分类模板；其他环境跳过 | `ProductPublishRpaRun/Log`           |
| 每 5 分钟    | 所有环境：主动查询本环境上架中任务            | `ProductPublishRpaRun/Log`           |

`dev/dev1/uat` 的前两个 Cron 只写应用跳过日志，不访问飞书或影刀，也不会创建同步批次。每 5 分钟结果轮询不能关闭，否则各环境自己的上架中任务无法自动取得 Amazon 结果。手工同步脚本不受该自动任务限制。

模板和结果查询均由后端主动调起影刀脚本。调度成功与 RPA 业务结果分阶段记录；本轮零条数据时仍应有 `SKIPPED` 运行记录。

单次 RPA 请求日志正常按 `DISPATCHING → WAITING_CALLBACK → PROCESSING_CALLBACK → SUCCESS/FAILED` 推进；确定性调度失败可从 `DISPATCHING` 进入 `FAILED`，回调落库失败或处理租约超时会从 `PROCESSING_CALLBACK` 释放回 `WAITING_CALLBACK`，超过本次日志 `expiresAt` 后进入 `TIMEOUT`（多类目批量默认 11400 秒）。启动尝试已受理不等于 Amazon 业务成功。

## 9. 接口验证

### 9.1 店铺与模板

```bash
curl -H "Authorization: Bearer <JWT>" \
  https://<API域名>/api/product-publish/stores
```

验收：

- 只有未禁用 Amazon 店铺。
- `externalStoreId` 是无精度丢失的字符串。
- 分类按 `sortOrder` 排序。
- RPA 模板任务成功后，`templateStatus=SUCCESS` 且 `templateUrl` 可公开下载。

### 9.2 提交上架

准备一条已完成 Excel、已绑定 Amazon 店铺的任务：

```bash
curl -X POST \
  -H "Authorization: Bearer <JWT>" \
  -H "Content-Type: application/json" \
  -d '{"fileUrl":"https://files.example.com/product-publish/listing.xlsm","skus":["SKU-001","SKU-002"]}' \
  https://<API域名>/api/product-publish/tasks/<taskId>/publish
```

验收：

- 异步返回 `accepted=true` 和 `requestId`，表示后端已受理并永久锁定本次提交；影刀接收结果可能已确认，也可能因网络异常暂时未知。
- 等待回调时任务保持 `COMPLETED`，但 `submitRequestId` 已非空并永久禁止重提；此时 `uploadId=null`。
- 输入 `task_id`/`rpa_storage` 均为空字符串；RPA 结果按 `business_id + file_url origin/pathname` 关联调度日志，`request_id` 可选。
- 结果接口处理后 `uploadId` 已保存，值为 Amazon 生成的业务批次 ID，同时任务变为 `PUBLISHING`。
- 重复执行同一命令返回 `409`，不会再次提交 Amazon。
- `fileUrl` 必须对应该任务已完成的 `spreadsheetUrl`；同一店铺和表格对象不能用于再次提交。
- `skus` 必须是本次 Excel 的完整非空 SKU 字符串数组；提交后保存到 `ProductPublishTask.skus` 并冻结，主动刷新和每 5 分钟轮询都会在 `check_feed_status.task_param` 中携带该列表。

### 9.3 主动刷新

先在另一个终端建立 SSE 连接：

```bash
curl -N \
  -H "Accept: text/event-stream" \
  -H "Authorization: Bearer <JWT>" \
  https://<API域名>/api/product-publish/events
```

```bash
curl -X POST \
  -H "Authorization: Bearer <JWT>" \
  https://<API域名>/api/product-publish/tasks/<taskId>/publish/refresh
```

验收：

- 请求异步返回 `accepted=true`，表示后端已受理一次查询启动尝试；影刀接收结果可能已确认，也可能因网络异常暂时未知。
- RPA 稍后 POST 结果，后端通过 `business_id + upload_id` 关联本次查询并落库，`request_id` 可选。
- 回调事务提交后 SSE 收到 `product-publish-refresh-completed`，其中 `taskId` 和 `requestId` 与主动刷新响应一致；前端据此停止刷新图标并重新拉取详情。
- 非终态继续 `PUBLISHING`。
- 终态恢复 `COMPLETED`，并有 `publishOutcome`、成功/失败数、结果文件及 SKU-ASIN 映射。

生产反向代理必须对 `/api/product-publish/events` 关闭 buffering/cache，并将读取超时调整到至少 1 小时。当前 SSE 事件总线是进程内实现；多副本部署时需把 SSE 和一键上架 RPA 回调固定到同一业务实例，或者在扩容前接入 Redis Pub/Sub。无论是否单实例，前端都保留任务详情低频轮询作为断线降级。

### 9.4 RPA 结果接口

先完成一次真实 `/publish` 调度，再使用相同的 `business_id + file_url origin/pathname` 联调：

```bash
curl -X POST \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: <YINGDAO_PRODUCT_PUBLISH_CALLBACK_API_KEY>' \
  -d '{"contract_version":"1.0","ok":true,"data":{"task_type":"upload_listing","business_id":"27826971599669","file_url":"https://files.example.com/product-publish/listing.xlsm","upload_id":"6b1ccdde-16f4-41e4-99d1-5d1ff273c02d"}}' \
  https://<API域名>/api/product-publish/internal/rpa/results
```

验收：

- API Key 错误返回 `401`。
- 无法匹配业务键的结果不得猜测落库。
- 同一业务键重复提交相同结果时幂等成功。
- 如果可选 `request_id` 非空，必须与业务键找回的内部日志一致。

### 9.5 上架记录

```bash
curl -H "Authorization: Bearer <JWT>" \
```

## 10. 故障处理

- 飞书同步失败：按 `runId` 查 `ProductPublishFeishuSyncRecord`，修复数据后重新执行同步脚本。
- 影刀鉴权失败：核对 accessKey 和 `YINGDAO_BASE_URL`，不在日志中打印 Secret。
- 找不到任务/应用：核对 `YINGDAO_PRODUCT_PUBLISH_TASK_UUID` 和 `YINGDAO_PRODUCT_PUBLISH_APP_ID`，确认应用已发布。
- 参数文件无法读取：确认应用输入参数名与 `YINGDAO_PRODUCT_PUBLISH_PARAM_NAME` 一致、类型为 `file`。
- RPA 回调到错误环境：核对 `YINGDAO_PRODUCT_PUBLISH_PROFILE`，并确认影刀应用按 `profile` 选择对应回调地址。
- 调度成功但结果超时：检查 RPA 脚本日志、结果接口 URL、`X-API-Key` 和 `YINGDAO_PRODUCT_PUBLISH_CALLBACK_TIMEOUT_SECONDS`。
- 结果无法关联：核对 `task_type` 对应业务键（模板为 `business_id + category`，提交为 `business_id + file_url origin/pathname`，查询为 `business_id + upload_id`）；不从空字符串 `task_id` 推导关联号。
- `uploadId` 错误：确认它是 Amazon 业务批次 ID，不是影刀 `taskUuid`/`jobUuid`。
- 上架请求结果不明：不得重新上架；根据原 `requestId`、RPA 日志和 Amazon 实际批次排查。

## 全部店铺模板单次同步

需要强制同步全部启用 Amazon 店铺的全部分类模板时，可执行：

```bash
npm run sync:product-publish-templates
```

脚本忽略最近同步时间，读取全部启用 Amazon 店铺及其分类映射，为每一项建立状态锁和 RPA 审计记录，然后逐条调起 `download_listing`。脚本会等待所有 RPA 请求正式回调接口；回调成功后将模板链接更新到店铺分类，最后统一输出每个店铺、分类、模板链接和执行状态。

默认等待时长读取本次批量日志的 `expiresAt`，另加 300 秒供超时扫描处理（默认批量窗口 11400 秒），联调时可临时覆盖：

```bash
npm run sync:product-publish-templates -- --wait-seconds 600
```

全量脚本每次运行都会按店铺聚合后批量强制执行全部店铺分类，失败后可以直接重新运行。分类存在旧的待回调 `download_listing` 时，脚本会把旧审计终结为 `TIMEOUT`、按请求 ID 原子释放旧锁并重新调度；若旧回调正在写库，则等待该事务结束后继续，不会跳过任何分类。该动作只获取模板，不会产生重复上架。执行期间，后端回调接口必须已部署并能被 RPA 访问。脚本超时退出不会删除新请求记录，后续到达的合法回调仍可正常落库，也可再次运行脚本重试。

## 11. 回滚原则

- 代码可回滚到前一版本。
- 新表、新字段保留，不直接删除，因为可能已被任务和审计数据引用。
- migration 没有自动 down 脚本；任何删表、删字段或恢复备份由 DBA 审批。
- 临时停止 RPA Cron 应通过部署编排保留唯一不执行 Cron 的实例方案，不通过删库或清空业务记录处理。

### 配置缺失错误不自动重试

失败补发扫描遇到当前 `lastSyncError` 或最新下载日志中包含「未查询到店铺」「传入密码为空」时，跳过该类目，不新建下载请求，不清空最近成功的模板 URL、成功时间或错误信息。页面仍可使用已保存模板；从未成功下载且没有模板 URL 的情况无法凭空恢复文件。普通登录失败、网络错误和超时仍按原重试策略处理。每日正常刷新与手工刷新保持可用，以便店铺或账号配置修复后重新获取模板。已经提交给 RPA 的运行中批次不受此跳过规则影响。
