# 车泰斗生图比例、尺寸前端联调文档

日期：2026-10-06。适用入口：车泰斗工作台。后端已实现；前端按本文接入。

本次增加比例与尺寸档位，保留 1/2/4/8 张。2026-10-07 起补充质量选择，完整契约见[车泰斗生图质量选择-前端联调文档](车泰斗生图质量选择-前端联调文档.md)。模型由后端查询数据库 `CHETAIDOU_IMAGE` 分类，前端不传模型 ID。已读取当前数据库确认：`gpt-image-2.5-sunburst` 启用，`ZQ-Image-2` 停用；当前模型 Schema 版本为 1。

所有请求带现有 Bearer Token，路径包含 `/api`。本次没有数据库表或字段变更，不需要 `db:push`。

## 1. 页面与参数

生成区增加“比例”和“尺寸”，保留“张数”。

| 控件 | 选项 / 初始值 | 提交值 |
|---|---|---|
| 比例 | 默认母版比例；10 个常用比例；自定义 | 实际 `aspectRatio`，如 `4:5`；自定义为 `custom` |
| 自定义宽 / 高 | 仅选自定义时显示 | `customAspectW` / `customAspectH`，JSON 数字、正安全整数 |
| 尺寸 | `1K` / `2K` / `4K`，默认 `1K` | `resolutionTier` |
| 张数 | `1` / `2` / `4` / `8` | `count`，JSON 数字 |
| 质量 | 标准 / 高清 | `quality=standard/hd`，2026-10-07 新增 |

比例宽高表达比例，不代表输出像素。输入 `166 × 182` 表示 `83:91`，不是生成 166×182 像素。

母版比例从图片接口的 `width` / `height` 计算并约分。例如 800×1000 提交 `4:5`。前端可用 `source` / `original` 表示界面内部选择，但这些值不能提交为 `aspectRatio`。母版尺寸缺失时应提示重新加载母版，不能悄悄改成正方形。

比例、尺寸和张数属于生成参数。修改这些控件不清空组合，不重新联想或组织提示词；只在创建 GENERATE 时提交。可保存在浏览器当前母版的本地状态，本次不增加服务端草稿字段。站点、文案、人物、选项变化仍按原流程使组合失效。

## 2. 前端自行初始化控件

比例、尺寸选项和默认值由前端维护，无需请求后端获取生图控件配置。GET /api/chetaidou/config 保持原有返回，本次不增加 imageGeneration 或其他生图选项字段。

前端自行提供母版比例、十个常用比例和自定义比例；尺寸提供 1K/2K/4K，默认选中 1K。生成时按下一节提交实际选择值。

沿用原有权限、模块开关和组合 READY 检查。后端在新建 GENERATE 时读取数据库模型、校验传入参数并执行尺寸适配；失败时按第 5 节处理错误，不通过新配置字段驱动控件。

## 3. 创建生图任务

`POST /api/chetaidou/tasks`，成功 HTTP 202。

| 字段 | 必填 | 说明 |
|---|---|---|
| `type` | 是 | 固定 `GENERATE` |
| `imageId` | 是 | 当前母版 ID，数字 |
| `compositionTaskId` | 是 | 当前已成功且 READY 的 COMPOSE 根任务 UUID |
| `idempotencyKey` | 是 | 本次提交 UUID；网络重试沿用原键及原参数 |
| `draftRevision` | 建议传 | 当前服务端草稿 revision，防止跨页面覆盖 |
| `count` | 是 | 1/2/4/8 |
| `aspectRatio` | 新任务必传 | 约分后的正整数 `宽:高`，或 `custom`；实际比例不限于预设十种 |
| `resolutionTier` | 否 | 推荐显式传大写 1K/2K/4K；省略时为 1K |
| `quality` | 否 | standard 标准 / hd 高清；省略时使用模型默认质量 |
| `customAspectW` | custom 时必传 | 正安全整数；非 custom 时不传 |
| `customAspectH` | custom 时必传 | 正安全整数；非 custom 时不传 |

可传 `quality`，不传 `model`、`prompt`、`resolution`、`size`、`customSizeMode`、参考图 URL。后端从已确认组合构造提示词、签名参考图，并冻结实际执行参数。

常用比例：

```json
{
  "type": "GENERATE",
  "imageId": 19,
  "compositionTaskId": "61c3a1a8-4ac5-4f7c-84f6-f524ea57bb24",
  "idempotencyKey": "cc92b568-57f3-4f47-8e11-4a1ea64a9fbf",
  "draftRevision": 6,
  "count": 4,
  "aspectRatio": "16:9",
  "resolutionTier": "2K"
}
```

自定义比例：

```json
{
  "type": "GENERATE",
  "imageId": 19,
  "compositionTaskId": "61c3a1a8-4ac5-4f7c-84f6-f524ea57bb24",
  "idempotencyKey": "c0f4f60f-8e3b-4d8a-8e2b-6168559dc5ea",
  "draftRevision": 6,
  "count": 2,
  "aspectRatio": "custom",
  "customAspectW": 166,
  "customAspectH": 182,
  "resolutionTier": "4K"
}
```

首次创建响应：

```json
{
  "taskId": "a7c301d4-88e4-4a13-8d8b-e22d977a49ae",
  "imageGenJobId": "69242dc8-89b2-4e83-a96f-53eacfbf4061",
  "status": "QUEUED",
  "items": [
    { "resultId": 310, "index": 1, "status": "QUEUED" },
    { "resultId": 311, "index": 2, "status": "QUEUED" }
  ]
}
```

沿用现有幂等响应行为：同键同请求重放返回任务详情，任务 ID 字段为 `id`。前端使用 `response.taskId ?? response.id`，然后读取任务详情。同键变更比例、尺寸或张数返回 409；用户主动改变参数再次生成必须分配新 UUID。网络超时不能自动换键重发。

尺寸档位大小写、空白会归一，例如 `" 2k "` 与 `"2K"` 等价。3K 仅用于老输入兼容，会转换为 2K 并提示，不放入新下拉列表。历史缺比例的同键请求仍可重放；新建缺比例请求返回 400。

## 4. 查询与结果展示

- `GET /api/chetaidou/tasks/:id`：生成任务详情。
- `GET /api/chetaidou/tasks`：任务列表，GENERATE 任务有相同新增字段。
- `GET /api/chetaidou/skus/:skuId/results`：预览墙，每项新增 `generation` / `generationMeta`。
- `GET /api/chetaidou/tasks/status?ids=...`：维持现有轻量状态轮询，未新增完整参数和交付信息；终态后获取详情或刷新预览墙。
- `GET /api/chetaidou/tasks/:id/output`：返回 items；整体生成参数请从任务详情取。
- `GET /api/chetaidou/results/:resultId/download`：沿用签名 URL、有效期及正确扩展名的文件名。

详情示例节选：用户选 2:3、4K，模型适配为 2K，原生图 1536×2048，最终只裁为 1365×2048。

```json
{
  "id": "a7c301d4-88e4-4a13-8d8b-e22d977a49ae",
  "type": "GENERATE",
  "status": "SUCCEEDED",
  "generation": {
    "model": "gpt-image-2.5-sunburst",
    "count": 1,
    "requestedAspectRatio": "2:3",
    "aspectRatio": "2:3",
    "resolutionTier": "4K",
    "resolution": "4k",
    "schemaVersion": 1,
    "providerApplied": { "aspect_ratio": "2:3", "resolution": "2k" },
    "warnings": ["清晰度档位 4k 超出模型尺寸能力，降档 2k 生成"],
    "sizingAdjustments": ["清晰度档位 4k 超出模型尺寸能力，降档 2k 生成"],
    "normalizationMode": "CROP_ONLY",
    "plannerVersion": "chetaidou-image-v1",
    "generationPromptVersion": "canvas-v1"
  },
  "items": [{
    "resultId": 310,
    "index": 1,
    "status": "SUCCEEDED",
    "url": "https://example.com/signed-result.jpg",
    "width": 1365,
    "height": 2048,
    "generationMeta": {
      "nativeWidth": 1536,
      "nativeHeight": 2048,
      "actual": { "width": 1365, "height": 2048, "format": "jpeg" },
      "providerApplied": { "aspect_ratio": "2:3", "resolution": "2k" },
      "normalized": {
        "from": "1536x2048",
        "to": "1365x2048",
        "ops": ["crop:cover+attention", "reencode:jpeg-94-4:4:4"]
      },
      "sizingAdjusted": ["清晰度档位 4k 超出模型尺寸能力，降档 2k 生成"],
      "adaptation": "CROP_ONLY",
      "warnings": ["清晰度档位 4k 超出模型尺寸能力，降档 2k 生成"]
    }
  }]
}
```

`requestedAspectRatio` 为用户输入方式（custom 时是 `custom`），`aspectRatio` 为解析后的实际目标比例（如 `83:91`）。`generation` 中的 `resolution` 是历史兼容镜像字段，前端选择及显示请求档位使用 `resolutionTier`。

结果卡片显示“请求 2:3 · 4K”及“实际 1365×2048”。根据单项 `generationMeta.warnings` 展示调整说明，整体 `generation.warnings` 可在任务提交后提前显示；重复文字可去重。历史任务可能无新增信息或为 null，保留原展示即可，不补写虚假的默认比例/档位。

`adaptation` 的含义：

| 值 | 展示含义 |
|---|---|
| `TARGET_SIZE` | 已按目标比例裁剪并归一到目标尺寸 |
| `CROP_ONLY` | 模型规格已适配；仅裁回比例，不放大补回原档位 |
| `UNCHANGED` | 原生产物已符合通用生图容忍范围，直接交付 |
| `NORMALIZATION_DISABLED` | 尺寸归一开关关闭或模型在豁免名单，保原图 |
| `SKIPPED_MAX_PIXELS` | 超过归一处理像素范围，保原图，不代表生成失败 |
| `KEPT_ORIGINAL` | 归一未完成或失败，保原图并提示 |
| `LEGACY_ORIGINAL` | 历史任务按原方式交付 |

`normalized=null` 不一定是原生尺寸匹配，应同时读取 `adaptation` 和 `warnings`。最终尺寸以 `items.width` / `items.height` 为准，不由前端按请求参数推算。裁剪使用通用生图的 cover+attention；透明图保留 PNG，其他需要重编码的图保存 JPEG。

## 5. 重试和错误处理

`POST /api/chetaidou/tasks/:id/retry`

```json
{
  "idempotencyKey": "517b77bb-1c79-432c-babb-87651d6c21f4",
  "resultIds": [310]
}
```

重试只针对 FAILED 项，继续使用原任务的模型、比例、尺寸、有效提示词和适配规划。不提交当前下拉框参数。需要改变参数时，从当前 READY 组合创建新的 GENERATE。

原模型停用后拒绝新重试，提示“该任务原生图模型已停用或不可用，请使用当前配置重新生成”。已提交调用和待交付产物继续使用原账单结算。`UNKNOWN` 等待对账，`DELIVERY_PENDING` 等待交付恢复，均不自动新建任务重发。

错误响应沿用：`{ statusCode, code?, message, details?, timestamp }`。DTO 校验时 message 可能是字符串数组，且不一定有 code。

| HTTP / code | 前端处理 |
|---|---|
| 400 / `IMAGE_GENERATION_PARAM_INVALID` | 提示补齐比例、修正宽高或尺寸档位 |
| 400 / `NEEDS_RESOLUTION` | 组合未 READY，继续原冲突问答流程 |
| 400 或 503 / `MODEL_NOT_READY` | 模型停用时引导重新生成，配置异常联系管理员；无需加载生图控件配置 |
| 409 / `MODEL_CONFIG_CHANGED` | 提示模型配置已更新，由用户重新提交，分配新幂等键 |
| 409 / `SETTINGS_CHANGED` | 拉取最新草稿和组合，不自动覆盖 |
| 409 / `IDEMPOTENCY_CONFLICT` | 检查是否把旧键用于了不同生成参数 |

## 6. 前端现有文件改动清单

对应 `chetaidou-studio-main/public/`：

1. `studio.html`：生成区加比例、尺寸选择器和自定义比例宽高输入；质量控件按 2026-10-07 补充文档接入。
2. `studio-draft.mjs`：保存每个母版的本地生成选择；旧草稿初始化为母版比例、1K；不把这些字段加入组合过期指纹。
3. `studio.js`：前端自行定义比例、尺寸选项和默认值；切换母版时使用该母版尺寸；生成前构造实际比例。
4. `studio-backend.mjs`：GENERATE body 加比例/尺寸及当前 revision；任务映射保留 generation、实际宽高、generationMeta；兼容首次 `taskId` 与幂等返回 `id`。
5. 任务墙/预览墙：从任务冻结参数展示请求规格，从 Item 显示实际宽高与 warnings；历史任务做缺字段兼容。

比例解析参考，API body 仍按第 3 节组装：

```js
function sourceRatio(width, height) {
  if (![width, height].every(n => Number.isSafeInteger(n) && n > 0)) {
    throw new Error("母版尺寸缺失，请重新加载母版")
  }
  let a = width, b = height
  while (b) [a, b] = [b, a % b]
  return `${width / a}:${height / a}`
}

function ratioFields(selection, image, customW, customH) {
  if (selection === "source") {
    return { aspectRatio: sourceRatio(image.width, image.height) }
  }
  if (selection !== "custom") return { aspectRatio: selection }
  const w = Number(customW), h = Number(customH)
  if (![w, h].every(n => Number.isSafeInteger(n) && n > 0)) {
    throw new Error("自定义比例宽高必须为正安全整数")
  }
  return { aspectRatio: "custom", customAspectW: w, customAspectH: h }
}
```

提交前如果调用了原有 `saveDraft`，要使用其返回的最新 revision。仅改变生成参数不必额外保存服务端草稿；保存语义内容不变的草稿虽保留组合指针，revision 仍会递增。

## 7. 联调与发布验收

| 场景 | 预期 |
|---|---|
| 默认母版 800×1000、1K、1 张 | 请求传 `4:5`，不传 `original` |
| 十个常用比例，各档位 | 可创建；参数在任务详情冻结 |
| 自定义 166:182 | 详情目标比例为 83:91；输出按比例裁剪 |
| 缺比例 / 0 / 小数 / 缺 custom 高 | 提示非法参数，不调用模型 |
| 切换比例、档位、张数 | 组合继续 READY，可再次生成 |
| 4K 被模型降档 | 展示请求 4K、实际宽高及调整说明；不补放大 |
| 网络重试 | 原键原参数，复用原任务 |
| 原键改变参数 | 409，不能重复创建 |
| 重试失败项 | 使用原参数；原模型停用时提示重新生成 |
| 透明图 / JPEG 图 | 预览正常，下载扩展名与实际格式一致 |
| 历史无 generation / meta | 无报错，沿用旧展示 |
| 归一关闭 / 归一失败 | 交付原图，显示实际宽高及提示 |

前后端应配套发布：新后端拒绝“新建 GENERATE 不传比例”，旧前端须同步更新。构建和自动测试已覆盖参数、幂等、冻结、共享裁剪、交付转存及模型切换；当前数据库 Schema 已验证 33 组规格。尚未发起付费网关生图或修改前端代码，真实图片生成、存储权限及页面显示由联调验收确认。

## 8. 其他环境的模型切换

脚本：`scripts/switch-chetaidou-image-model.ts`。当前检查的库已配置正确，无需重复 apply。

```bash
# 预览，<旧模型> 替换为目标库当前启用 publicId
node --env-file-if-exists=.env -r ts-node/register \
  scripts/switch-chetaidou-image-model.ts \
  --from=<旧模型> --to=gpt-image-2.5-sunburst --dry-run

# 正式切换；备份路径不可已存在
node --env-file-if-exists=.env -r ts-node/register \
  scripts/switch-chetaidou-image-model.ts \
  --from=<旧模型> --to=gpt-image-2.5-sunburst \
  --apply --backup=seedbackups/chetaidou-image-switch.json

# 恢复预览，正式恢复将 --dry-run 改为 --apply
node --env-file-if-exists=.env -r ts-node/register \
  scripts/switch-chetaidou-image-model.ts \
  --restore=seedbackups/chetaidou-image-switch.json --dry-run
```

新目标行默认继承旧行价格；已有目标行保留其价格。首次切换可显式传 `--priceMultiplier=3`、`--fixedCredits=7` 或 `--fixedCredits=null`。若目标已经唯一启用，脚本幂等退出，不覆盖价格。切换前验证目标完整 Schema；备份写入成功才提交事务。恢复拒绝覆盖切换后的人工改动，并保留新模型行但停用，供历史账单继续引用。
