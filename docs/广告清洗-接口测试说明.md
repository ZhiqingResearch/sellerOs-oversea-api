# 广告清洗接口测试说明（第一版）

## 1. 功能范围

- 上传 Amazon Sponsored Products 搜索词报告（`.xlsx`）。
- 后端异步清洗，MySQL 只保存任务状态和最终文件 URL，不保存广告逐行数据。
- 清洗完成后生成新的 Excel，并上传到文件服务器。
- 输出固定包含 7 个 Sheet：清洗摘要、按广告活动、按广告组、按投放、按匹配类型、搜索词审计、待否定词。

所有接口均需要登录后的 JWT。项目全局接口前缀为 `/api`。

## 2. 创建清洗任务

```http
POST /api/ad-cleaning/tasks
Content-Type: multipart/form-data
Authorization: Bearer <JWT>
```

表单字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | file | 是 | `.xlsx` 文件，最大 50 MB、5 万数据行、200 列 |

curl 示例：

```bash
curl -X POST 'http://localhost:8000/api/ad-cleaning/tasks' \
  -H 'Authorization: Bearer <JWT>' \
  -F 'file=@/Users/zqzx/Downloads/Sponsored_Products_Search_term_report.xlsx'
```

成功时返回 HTTP `202`：

```json
{
  "taskId": "8d4dd930-2e77-40a8-9f79-e422c14f5a6c",
  "status": "PROCESSING",
  "progress": 1,
  "stage": "正在启动清洗任务",
  "originalFilename": "Sponsored_Products_Search_term_report.xlsx",
  "outputFilename": null,
  "resultFileUrl": null,
  "stats": null,
  "sheetPreviews": null,
  "errorMessage": null,
  "createdAt": "2026-08-20T10:00:00.000Z",
  "startedAt": "2026-08-20T10:00:00.001Z",
  "completedAt": null,
  "downloadPath": null
}
```

## 3. 查询任务状态

```http
GET /api/ad-cleaning/tasks/:taskId
Authorization: Bearer <JWT>
```

curl 示例：

```bash
curl 'http://localhost:8000/api/ad-cleaning/tasks/<taskId>' \
  -H 'Authorization: Bearer <JWT>'
```

状态流转：

```text
PENDING → PROCESSING → SUCCESS
                     ↘ FAILED
```

建议前端每 1～2 秒轮询一次，直到 `SUCCESS` 或 `FAILED`。成功后响应会包含：

- `resultFileUrl`：清洗结果在文件服务器上的稳定 URL。
- `downloadPath`：当前后端的下载入口，调用后会重定向到 `resultFileUrl`。
- `sheetPreviews`：中间 5 个 Sheet 各自的表头、前 100 条数据和完整数据行数。
- `stats`：后端读取“清洗摘要”后还原的汇总统计，但不会返回“清洗摘要”的行预览。

`sheetPreviews` 的结构示例：

```json
[
  {
    "sheetName": "搜索词审计",
    "headers": ["广告活动", "广告组", "投放", "匹配类型", "客户搜索词", "点击量"],
    "rows": [
      ["活动A", "广告组A", "laptop", "exact", "laptop stand", 12]
    ],
    "totalRows": 2913
  }
]
```

接口只返回以下 5 个 Sheet 的预览：按广告活动、按广告组、按投放、按匹配类型、搜索词审计。第一个“清洗摘要”和最后一个“待否定词”仍存在于完整 Excel 中，但不返回给前端展示。

表头不计入 100 条数据；数字保持 JSON `number`，空单元格返回 `null`。预览不写入 MySQL，也不做内存缓存；每次查询 `SUCCESS` 任务时，后端都会根据 `resultFileUrl` 实时读取 Excel。失败后读取 `errorMessage`。

## 4. 下载结果

```http
GET /api/ad-cleaning/tasks/:taskId/download
Authorization: Bearer <JWT>
```

curl 示例：

```bash
curl 'http://localhost:8000/api/ad-cleaning/tasks/<taskId>/download' \
  -H 'Authorization: Bearer <JWT>' \
  --output '广告搜索词-清洗结果.xlsx'
```

只有任务状态为 `SUCCESS` 时可以下载。接口返回 HTTP `302`，重定向到数据库中保存的 `resultFileUrl`。

## 5. 第一版限制与错误说明

- 只支持 `.xlsx`，不支持 `.xls`、`.csv`。
- 单文件只支持一种币种。
- 缺少必填表头、存在未知匹配类型、必填维度为空、非空非法数值、负数、公式单元格等情况会使整份文件失败。
- 最多同时容纳 10 个待处理/处理中的任务，采用单 Worker 串行清洗。
- 单任务最长运行 10 分钟，超时会失败并提示拆分文件。
- 任务状态和结果 URL 保存在 MySQL；原始文件只在本地临时目录存在。
- 服务重启前仍为 `PENDING` 或 `PROCESSING` 的任务会标记为失败，需要重新上传原文件。
- Sheet 前 100 行预览不写入数据库、不做内存缓存；每次查询成功任务都会读取一次文件服务器上的完整 Excel。
- 任务只允许创建它的用户查询和下载。

可在 Swagger 页面 `http://localhost:8000/api-docs` 中直接选择“广告数据清洗”分组进行测试。
