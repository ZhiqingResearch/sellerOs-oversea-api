# 智能定价记录前端联调文档

> 后端实现日期：2026-08-25
>
> 接口前缀：`/api/smart-pricing/records`
>
> Swagger：`/api-docs`
>
> 认证：Bearer JWT；本期不校验菜单或功能权限。

## 1. 接入结论

前端在完整定价报告成功生成后，调用一次创建接口归档。历史记录详情返回创建时的完整结构化快照，前端直接交给现有定价报告组件渲染，不需要重新解析采购链接、查询竞品、重新计算定价或调用模型。

本期四个接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/smart-pricing/records` | 归档一份完整定价报告 |
| `GET` | `/api/smart-pricing/records` | 当前用户的分页记录列表 |
| `GET` | `/api/smart-pricing/records/:recordId` | 获取完整定价快照 |
| `DELETE` | `/api/smart-pricing/records/:recordId` | 软删除当前用户的一条记录 |

所有请求携带：

```http
Authorization: Bearer <JWT_TOKEN>
```

用户只能访问自己的记录。其他用户的 UUID 也会返回 404。

## 2. 前端调用时机

推荐流程：

```text
用户确认最终输入
  → 链接解析/竞品分析/定价计算完成
  → 已得到完整 PricingResult
  → 生成 clientRequestId
  → POST 归档
  → 保存成功后刷新“定价记录”列表
```

注意：

1. 不要在报告还未生成完整时调用创建接口。
2. 同一次归档的网络重试必须复用相同 `clientRequestId` 和相同请求体。
3. 用户重新生成或修改参数后再次归档，应生成新的 `clientRequestId`。
4. 如果第一次请求超时且不知道是否成功，直接用原 UUID 和原请求体重试。
5. 查看历史详情时不能再次调用原来的 `pricingRun`、链接解析或竞品接口。

UUID 使用：

```ts
const clientRequestId = crypto.randomUUID()
```

不要在每次 Axios/fetch 重试前重新生成 UUID。

## 4. 站点字段映射

当前页面已有展示字段，例如：

```ts
market = "Amazon US"
```

提交前转换为 code/name：

```ts
const MARKETPLACE_CODE_BY_NAME: Record<
  string,
  SmartPricingMarketplaceCode
> = {
  "Amazon US": "AMAZON_US",
  "Walmart US": "WALMART_US",
  "Amazon UK": "AMAZON_UK",
  "Amazon DE": "AMAZON_DE",
  "TikTok MX": "TIKTOK_MX",
}

function buildMarketplace(marketplaceName: string) {
  const marketplaceCode = MARKETPLACE_CODE_BY_NAME[marketplaceName]
  if (!marketplaceCode) {
    throw new Error(`未配置的智能定价站点：${marketplaceName}`)
  }
  return { marketplaceCode, marketplaceName }
}
```

后端会严格校验 code/name 配对。例如 `AMAZON_US + Walmart US` 会返回 400。

不要只提交国家代码 `US`。`currency` 按页面实际计算币种传值（当前支持 `USD` / `MXN` / `GBP` / `EUR`，大小写均可，后端会转大写）：

```ts
// 例如 TikTok MX 页面按 MXN 计算时：
currency: "MXN"
```

### 5.1 Axios 调用示例

如果 Axios 的 `baseURL` 已经包含 `/api`，请去掉下面路径中的 `/api`。

```ts
async function archivePricingRecord(
  payload: CreateSmartPricingRecordRequest,
) {
  const { data } = await api.post<CreateSmartPricingRecordResponse>(
    "/api/smart-pricing/records",
    payload,
  )
  return data
}
```

### 5.2 关键校验

- `schemaVersion` 当前必须是 `1`。
- `currency` 必须属于白名单 `USD` / `MXN` / `GBP` / `EUR`（大小写均可，后端转大写）。
- `product.name.trim()` 必须与 `result.name.trim()` 一致。
- `result` 中的 `cost/freight/fba/commR/acosR/retR/vatR/premium/targetM` 必须与 `input` 一致。
- 输入成本、价格、阶段价格和瀑布金额不能为负数。
- `recNet/recMargin` 可以为负数。
- 所有输入费率范围为 `0～1`。
- 四个子评分及 `composite` 范围为 `0～100`。
- `stages` 必须正好四项，每项长度必须是 4。
- `vatR === 0` 时 `waterfall` 必须四项。
- `vatR > 0` 时 `waterfall` 必须五项，并包含 VAT 项。
- 所有颜色必须是六位 HEX，如 `#34c759`，不能传 `red` 或三位 HEX。
- 完整快照不能超过 1 MiB。

### 5.3 来源字段

后端保存 `sourceUrl` 前会只保留 `origin + pathname`，移除 query、hash 和 URL 中的账号信息。

如果 `sourceText` 本身是 HTTP(S) URL，也会执行相同清理。因此详情接口返回的 URL 可能与创建请求不完全相同，这是预期行为。

`filenames` 只能传文件名：

```ts
filenames: ["采购报价.pdf"] // 正确
filenames: ["C:\\Users\\me\\采购报价.pdf"] // 错误
```

## 6. 记录列表


筛选规则：

- `keyword` 同时模糊匹配产品名、站点展示名、类目。

- 多个筛选条件之间是 AND。
- 默认按 `createdAt DESC` 排序。

### 6.1 今天和近 7/30/90 天

后端把日期参数解释为北京时间自然日。不要使用 UTC `toISOString().slice(0, 10)` 直接获取“今天”，否则在北京时间 00:00～08:00 会得到前一天。

无额外日期库时可使用：

```ts
function shanghaiDate(offsetDays = 0): string {
  const parts = new Intl.DateTimeFormat("en-CA", {
    timeZone: "Asia/Shanghai",
    year: "numeric",
    month: "2-digit",
    day: "2-digit",
  }).formatToParts(new Date())

  const part = (type: Intl.DateTimeFormatPartTypes) =>
    Number(parts.find(item => item.type === type)?.value)

  const utcDay = Date.UTC(part("year"), part("month") - 1, part("day"))
  return new Date(utcDay + offsetDays * 86_400_000)
    .toISOString()
    .slice(0, 10)
}

const today = {
  dateFrom: shanghaiDate(0),
  dateTo: shanghaiDate(0),
}

const recent7Days = {
  dateFrom: shanghaiDate(-6),
  dateTo: shanghaiDate(0),
}

const recent30Days = {
  dateFrom: shanghaiDate(-29),
  dateTo: shanghaiDate(0),
}

const recent90Days = {
  dateFrom: shanghaiDate(-89),
  dateTo: shanghaiDate(0),
}
```

## 8. 删除记录

```http
DELETE /api/smart-pricing/records/:recordId
```

成功返回 HTTP 204，无响应体：

```ts
async function deletePricingRecord(recordId: string) {
  await api.delete(`/api/smart-pricing/records/${recordId}`)
}
```

建议等待 204 后再从列表移除。删除后：

- 列表和详情都无法再查询该记录。
- 原 `clientRequestId` 不能再次使用。
- 用户重新生成定价时必须创建新的 UUID。

## 9. 错误响应

业务错误结构：

```ts
export interface ApiErrorResponse {
  statusCode: number
  code?: string
  message: string | string[]
  details?: Record<string, unknown>
  timestamp: string
}
```

常见错误：

| HTTP | code | 前端处理建议 |
| --- | --- | --- |
| 400 | `INVALID_SMART_PRICING_RECORD` | 展示 message，检查站点映射、数组数量或跨字段一致性 |
| 400 | `INVALID_DATE_RANGE` | 重置日期筛选并提示用户 |
| 400 | `UNSUPPORTED_SMART_PRICING_SCHEMA_VERSION` | 提示刷新页面或升级前端 |
| 401 | 无固定业务 code | 登录失效，进入统一登录处理 |
| 404 | `SMART_PRICING_RECORD_NOT_FOUND` | 提示记录不存在并刷新列表 |
| 409 | `CLIENT_REQUEST_ID_REUSED` | 当前请求内容已变化，生成新的 UUID 后重新归档 |
| 409 | `SMART_PRICING_RECORD_ALREADY_DELETED` | 生成新的 UUID 后重新归档 |
| 413 | `SMART_PRICING_RECORD_PAYLOAD_TOO_LARGE` | 不要保存大文本、Base64、DOM 或过量竞品数据 |

DTO 基础类型校验失败时可能没有 `code`，但会返回 `statusCode=400` 和字符串数组 `message`，前端错误处理不能假设 `code` 一定存在。

Axios 示例：

```ts
function getApiErrorMessage(error: unknown): string {
  if (!axios.isAxiosError<ApiErrorResponse>(error)) {
    return "保存智能定价记录失败"
  }
  const message = error.response?.data?.message
  if (Array.isArray(message)) return message.join("；")
  return message || "保存智能定价记录失败"
}
```

## 10. 联调检查清单

- [ ] 请求携带有效 JWT。
- [ ] 页面展示站点已转换为 `marketplaceCode + marketplaceName`。
- [ ] `currency` 按页面实际计算币种传值（`USD` / `MXN` / `GBP` / `EUR`）。
- [ ] 每次新报告只生成一次 `clientRequestId`。
- [ ] 网络重试复用原 UUID 和原请求体。
- [ ] `product.name` 与 `result.name` 一致。
- [ ] result 中重复费率和成本与 input 一致。
- [ ] 所有输入费率传小数，不传 15、18、32。
- [ ] `recMargin` 传百分数 16.7113，不传 0.167113。
- [ ] stages 正好四项。
- [ ] vatR=0 时 waterfall 四项，vatR>0 时五项。
- [ ] 竞品失败传 `competitorContext=null`。
- [ ] filenames 不包含本地路径。
- [ ] 查看历史时只请求详情，不重新执行定价流程。
- [ ] 日期按钮按北京时间生成 YYYY-MM-DD。
- [ ] 列表直接使用 `netMargin` 显示百分数，不再乘 100。
- [ ] 204 删除响应不尝试解析 JSON。
