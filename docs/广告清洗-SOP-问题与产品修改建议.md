# 广告清洗 SOP 问题与产品修改建议（已确认）

> 用途：供产品基于原始文件 `广告清洗-SOP（开发实施版）.md` 修订业务口径和输出规格。
> 样例数据：`Sponsored_Products_Search_term_report.xlsx`。
> 当前范围：第一版实现“上传原始表格 → 清洗 → 生成新的 Excel → 上传文件服务器”。MySQL 只保存任务状态和清洗结果 URL，不保存原始数据、清洗明细或 Sheet 预览。
> 产品确认：2026-08-20，文档中的推荐项全部采用。

## 二、SOP 中必须修正的问题

### 1. 订单列表头无法匹配

样例原表的订单列为：

```text
7 Day Total Orders (#)
```

当前 SOP 的英文别名只有：

```text
7 Day Total Orders
```

参考代码不会删除 `#`，因此会误报“缺少订单列”。

建议修改：

- 为订单列增加 `7 Day Total Orders (#)` 别名。
- 表头归一化时删除空格、括号、`#` 和 BOM。

### 2. 文档声称支持全半角，但参考代码没有实现

当前参考代码只删除空格和括号，没有处理真正的全角/半角字符差异。

建议将表头归一化规则明确修改为：

```text
字符串化
→ Unicode NFKC 归一化
→ 删除 BOM
→ 删除空格、英文/中文括号和 #
→ 转小写
→ 使用别名精确匹配
```

### 3. 必填列定义不足

当前 SOP 只要求缺少 5 个原始量字段时报错，但缺少币种或任意维度字段时，同样无法完成分层聚合、金额格式化和审计。

建议将以下 11 个字段全部定义为必填字段：

```text
currency
campaign
adGroup
targeting
matchType
searchTerm
imp
clk
spend
sales
orders
```

缺少任一字段都应明确提示具体缺失列，并终止清洗。

### 4. 搜索词审计表的维度数量冲突

SOP 的完整聚合键是：

```text
活动 + 广告组 + Targeting + Match Type + Search Term
```

这是 5 个维度，但输出规格写的是“4 个维度”。

样例数据验证结果：

- 如果不输出 Targeting，会出现 58 组外观看起来重复的记录。
- 如果不输出 Match Type，会出现 13 组外观看起来重复的记录。

确认口径：搜索词审计表保留全部 5 个维度，避免用户无法区分不同投放来源的数据。

### 5. 指标数量冲突

`_adMetrics` 定义了 6 个指标：

```text
CTR、CPC、CVR、ACOS、CPA、ROAS
```

输出规格却写“5 个指标”，并限定逐词导出为 22 列。

确认口径：输出全部 6 个指标并保留 ROAS，所有结果表和字段说明均按 6 个指标定义。

### 6. CPA 的零分母规则错误

当前边界条件写“全表销售额为 0 时，ACOS、CPA 全部显示 `—`”。该规则不正确：

- ACOS 的分母是销售额。
- CPA 的分母是订单数。

确认口径：

```text
sales > 0  → ACOS = spend / sales
sales = 0  → ACOS = null，Excel 显示“—”

orders > 0 → CPA = spend / orders
orders = 0 → CPA = null，Excel 显示“—”
```

### 7. 全站 ACOS 的空值口径冲突

SOP 前面规定分母为 0 时返回 `null`，后面又规定全站销售额为 0 时“全站均 ACOS 记 0”，两个口径互相冲突。

确认口径：

- 全站销售额为 0 时，全站 ACOS 为 `null`，展示为 `—`。
- 判断函数需要显式处理 `siteAcos === null`，不得依靠 JavaScript 将 `null` 隐式转换为 0。
- 没有有效全站 ACOS 基准时，不执行“高于全站 ACOS 1.5 倍”和“低于全站 ACOS”的判断。

### 8. `bad` 不能全部命名为“待否定”

`bad` 同时包含：

1. 零订单且高点击的无效搜索词，适合否定。
2. 有订单但 ACOS 过高的搜索词，适合降价控成本，不适合直接否定。

样例文件中：

- `bad` 共 29 条。
- 真正满足 `bad && orders === 0` 的待否定词为 28 条。
- 28 条待否定词的浪费花费合计为 `$631.52`。

确认口径：

- 汇总数量将 `bad` 命名为“高风险”。
- 待否定清单继续严格筛选 `cls === "bad" && orders === 0`。
- 有订单但 ACOS 过高的记录只给出“降价控成本”建议。

### 9. 输出数量描述冲突

文档开头写“5 张分层汇总表 + 1 张逐词审计表 + 1 份待否定清单”，后面又将逐词审计包含在 5 个 Tab 中。

确认第一版统一为 7 个 Excel Sheet：

1. 清洗摘要
2. 按广告活动
3. 按广告组
4. 按投放
5. 按匹配类型
6. 搜索词审计
7. 待否定词

## 三、样例原始数据中的异常

### 1. 曝光量为 0，但点击量为 1

样例中有 2 条此类数据，无法计算 CTR。

确认处理方式：

- 保留原始记录和花费，不直接删除。
- CTR 输出为空值，Excel 显示 `—`。
- 判断证据增加“源数据曝光为 0”的异常说明。
- 在“清洗摘要”中记录异常数量。

### 2. 搜索词包含不可见字符

样例中有 12 条搜索词包含共 13 个不可见字符 `U+FFFC`，可能导致搜索、聚合、去重和否定词提交失败。

确认处理方式：聚合前删除 `U+FFFC`，并在清洗摘要中记录清理数量。

### 3. 搜索词被首尾双引号包裹

样例中有 2 条，例如：

```text
"hp 17 backlit keyboard 1tb ssd"
```

确认处理方式：仅当首尾引号成对包裹整条搜索词时删除首尾引号；不要删除搜索词中间的正常引号。

### 4. 同名广告组跨活动重复

样例中有 10 个广告组名称被不同广告活动重复使用。

确认处理方式：广告组必须使用“活动 + 广告组”作为组合键，禁止只按广告组名称聚合。

## 四、建议补充的数据清洗规则

### 1. 非法数值处理

当前 SOP 规定 `NaN` 直接记 0，这可能把源文件错误静默转成正常数据。

确认处理方式：

- 空白数值按 0 处理。
- 非空但无法解析的数值视为文件错误。
- 错误信息必须包含 Sheet、Excel 行号、列名和原始值。
- 发现非法数值后终止整份文件清洗，不生成看似正常的结果。

### 2. 币种处理

样例文件全部为 USD，可以使用 `$` 格式。

确认第一版限制：

- 单个文件只允许一种币种。
- 出现多币种时终止清洗，并提示不能直接汇总不同币种的金额。
- 输出金额格式根据 Currency 字段选择，不在数值中写入货币符号文本。

### 3. 搜索词文本处理

确认以下处理顺序：

```text
字符串化
→ 去首尾空白
→ 删除 U+FFFC
→ 删除成对包裹整条内容的首尾引号
→ 再次去首尾空白
→ 保留原始大小写
```

不得对搜索词统一转小写，否则输出将不能保持原始展示。

### 4. Excel 数据类型

输出 Excel 时：

- 展示量、点击量、订单数写为数值。
- 花费、销售额、CPC、CPA写为数值并应用货币格式。
- CTR、CVR、ACOS写为 0～1 的数值并应用 `0.00%` 格式。
- ROAS写为数值，不写成文本。
- 分母为 0 的指标写为空单元格，显示层使用 `—`。
- 搜索词、活动、广告组、Targeting、Match Type写为文本。

## 五、已确认的搜索词审计表字段

搜索词审计表采用“5 个维度 + 6 个指标”，固定包含以下 24 列：

| 分类 | 字段 |
|---|---|
| 5个维度 | 广告活动、广告组、投放、匹配类型、客户搜索词 |
| 5个原始量 | 展示量、点击量、花费、7天销售额、7天订单数 |
| 6个重算指标 | CTR、CPC、CVR、ACOS、CPA、ROAS |
| 6个对比基准 | 活动均CTR、广告组均CTR、匹配类型均CTR、全站均CTR、全站均CVR、全站均ACOS |
| 2个结论字段 | 判断、清洗建议 |

所有结果表默认按花费降序。

## 六、已确认的待否定词 Sheet

筛选条件：

```text
cls === "bad" && orders === 0
```

固定字段：

| 字段 | 说明 |
|---|---|
| 广告活动 | 来源活动 |
| 广告组 | 来源广告组 |
| 投放 | 原 Targeting |
| 匹配类型 | 原 Match Type |
| 客户搜索词 | 待否定词 |
| 建议否定匹配 | 默认 Negative Exact |
| 点击量 | 判断证据 |
| 花费 | 浪费花费 |
| 判断证据 | 例如“点击 38 / 订单 0” |

按花费降序，表格末尾增加待否定词数量和总浪费花费。

## 七、已确认的第一版产品范围

第一版只包含：

- 上传 `.xlsx` 文件。
- 异步清洗并查询进度。
- 生成新的 `.xlsx` 文件。
- 按 Sheet 输出汇总、审计和待否定清单。
- 下载清洗结果。
- 原始数据和清洗数据不写入 MySQL。

第一版暂不包含：

- CSV 导出。
- 清洗结果在线编辑或确认。
- 前端虚拟表格和五类胶囊筛选。
- ASIN 审计、广告问题诊断和广告评分。
- 清洗任务历史持久化。
- 多币种汇率换算。

确认限制：

- 单文件最大 50 MB。
- 单文件最大 5 万条数据。
- 同时只运行 1 个清洗任务。
- 任务状态只保存在内存中，服务重启后任务需要重新上传。
