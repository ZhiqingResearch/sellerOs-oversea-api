# 广告清洗前端联调文档

> 版本：第一版
> 更新时间：2026-08-21
> 后端默认地址：`http://localhost:8000`
> Swagger：`http://localhost:8000/api-docs`

## 1. 功能说明

前端上传 Amazon Sponsored Products 搜索词报表后，后端异步完成数据清洗、生成新的 Excel，并上传到文件服务器。

前端通过任务接口查询清洗进度。任务成功后，接口会返回：

- 清洗结果文件 URL；
- 清洗统计数据；
- 5 个中间 Sheet 的前 100 行数据，用于前端预览；
- 后端下载接口地址。

完整处理流程如下：

```text
选择 Excel
   ↓
创建清洗任务
   ↓
每 1.5～2 秒查询任务状态
   ↓
PENDING / PROCESSING：继续等待
   ↓
SUCCESS：停止轮询，展示统计、Sheet 预览和下载按钮
FAILED：停止轮询，展示错误并允许重新上传
```

## 2. 联调前提

### 2.1 请求认证

三个接口都需要登录，并在请求头携带 JWT：

```http
Authorization: Bearer <access_token>
```

用户只能查询和下载自己创建的任务。

### 2.2 后端准备

联调前需要确认：

- 已执行广告清洗任务表对应的 Prisma migration；
- 后端服务已启动；
- 文件服务器配置可用；
- 当前登录用户可以正常获取 JWT。

### 2.3 文件限制

| 项目 | 限制 |
| --- | --- |
| 文件格式 | 第一版只支持 `.xlsx` |
| 文件大小 | 不超过 50 MB |
| 最大数据行 | 50,000 行 |
| 最大列数 | 200 列 |
| 币种 | 单次文件只能包含一个币种 |
| 并发队列 | 系统最多允许 10 个等待中或处理中的任务 |
| 单任务超时 | 10 分钟 |

上传时，`multipart/form-data` 的字段名必须是 `file`。

## 3. 接口总览

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| `POST` | `/api/ad-cleaning/tasks` | 上传原始 Excel，创建异步清洗任务 |
| `GET` | `/api/ad-cleaning/tasks/:taskId` | 查询进度；成功后获取统计、预览和文件 URL |
| `GET` | `/api/ad-cleaning/tasks/:taskId/download` | 校验任务归属后，重定向到结果文件 URL |

```ts
  completedAt: string | null;

  downloadPath: string | null;

export interface ApiErrorResponse {
  statusCode: number;
  message: string | string[];
  timestamp: string;
}

export class ApiRequestError extends Error {
  constructor(
    public readonly status: number,
    message: string,
  ) {
    super(message);
    this.name = 'ApiRequestError';
  }
}

export async function throwApiError(response: Response): Promise<never> {
  const error = (await response.json().catch(() => null)) as ApiErrorResponse | null;
  const message = Array.isArray(error?.message)
    ? error.message.join('；')
    : error?.message || `请求失败（HTTP ${response.status}）`;

  throw new ApiRequestError(response.status, message);
}
```

## 5. 创建清洗任务

### 5.1 请求

```http
POST /api/ad-cleaning/tasks
Authorization: Bearer <access_token>
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | File | 是 | 待清洗的 `.xlsx` 或 `.xls` 文件 |

浏览器使用 `FormData` 时，不要手动设置 `Content-Type`，浏览器会自动补充 multipart boundary。

```ts
export async function createAdCleaningTask(
  apiBaseUrl: string,
  token: string,
  file: File,
): Promise<AdCleaningTask> {
  const formData = new FormData();
  formData.append('file', file);

  const response = await fetch(`${apiBaseUrl}/api/ad-cleaning/tasks`, {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${token}`,
    },
    body: formData,
  });

  if (!response.ok) {
    return throwApiError(response);
  }

  return response.json() as Promise<AdCleaningTask>;
}
```

### 5.2 响应

HTTP 状态码：`202 Accepted`

```json
{
  "taskId": "cmf1234567890",
  "status": "PENDING",
  "progress": 0,
  "stage": "等待处理",
  "originalFilename": "Sponsored_Products_Search_term_report.xlsx",
  "outputFilename": null,
  "resultFileUrl": null,
  "stats": null,
  "sheetPreviews": null,
  "errorMessage": null,
  "createdAt": "2026-08-21T02:30:00.000Z",
  "startedAt": null,
  "completedAt": null,
  "downloadPath": null
}
```

任务创建后会立即进入队列，因此接口返回时也可能已经是 `PROCESSING`，前端不能只按 `PENDING` 判断创建是否成功。

## 6. 查询任务状态

### 6.1 请求

```http
GET /api/ad-cleaning/tasks/:taskId
Authorization: Bearer <access_token>
```

```ts
export async function getAdCleaningTask(
  apiBaseUrl: string,
  token: string,
  taskId: string,
): Promise<AdCleaningTask> {
  const response = await fetch(
    `${apiBaseUrl}/api/ad-cleaning/tasks/${encodeURIComponent(taskId)}`,
    {
      headers: {
        Authorization: `Bearer ${token}`,
      },
    },
  );

  if (!response.ok) {
    return throwApiError(response);
  }

  return response.json() as Promise<AdCleaningTask>;
}
```

### 6.2 状态说明

| 状态 | 含义 | 前端处理 |
| --- | --- | --- |
| `PENDING` | 已进入队列，等待 Worker | 展示排队中，继续轮询 |
| `PROCESSING` | 正在解析、清洗、生成或上传文件 | 展示 `progress` 和 `stage`，继续轮询 |
| `SUCCESS` | 清洗完成 | 立即停止轮询，展示统计、预览和下载入口 |
| `FAILED` | 清洗失败或任务超时 | 立即停止轮询，展示 `errorMessage` 和重新上传按钮 |

### 6.4 预览 Sheet 范围

最终 Excel 共包含 7 个 Sheet：

1. 清洗摘要；
2. 按广告活动；
3. 按广告组；
4. 按投放；
5. 按匹配类型；
6. 搜索词审计；
7. 待否定词。

接口只向前端返回中间 5 个 Sheet：

- 按广告活动；
- 按广告组；
- 按投放；
- 按匹配类型；
- 搜索词审计。

第一个 Sheet“清洗摘要”和最后一个 Sheet“待否定词”不返回前端预览，但仍会完整写入下载的 Excel。

每个预览最多 100 行。`totalRows` 是该 Sheet 的完整数据行数，前端建议显示：

```text
当前展示前 100 行，共 2,913 行；完整数据请下载 Excel 查看。
```

当前没有预览分页接口，前端不要基于 `totalRows` 请求第 101 行之后的数据。

## 7. 前端轮询实现

建议轮询间隔为 1.5～2 秒，并在组件卸载或用户离开页面时主动取消。

```ts
function wait(ms: number, signal?: AbortSignal): Promise<void> {
  return new Promise((resolve, reject) => {
    const timer = window.setTimeout(resolve, ms);

    signal?.addEventListener(
      'abort',
      () => {
        window.clearTimeout(timer);
        reject(new DOMException('轮询已取消', 'AbortError'));
      },
      { once: true },
    );
  });
}

export async function pollAdCleaningTask(options: {
  apiBaseUrl: string;
  token: string;
  taskId: string;
  onUpdate: (task: AdCleaningTask) => void;
  signal?: AbortSignal;
}): Promise<AdCleaningTask> {
  const { apiBaseUrl, token, taskId, onUpdate, signal } = options;

  while (!signal?.aborted) {
    try {
      const task = await getAdCleaningTask(apiBaseUrl, token, taskId);
      onUpdate(task);

      if (task.status === 'SUCCESS' || task.status === 'FAILED') {
        return task;
      }
    } catch (error) {
      if (signal?.aborted) {
        throw error;
      }

      const retryable =
        error instanceof TypeError ||
        (error instanceof ApiRequestError && error.status === 503);

      if (!retryable) {
        throw error;
      }

      // 网络异常或成功文件预览读取失败时，等待后重试当前任务。
      // 不要因为一次查询失败而重新创建清洗任务。
    }

    await wait(1500, signal);
  }

  throw new DOMException('轮询已取消', 'AbortError');
}
```

关键约定：

- 收到第一次 `SUCCESS` 后必须停止轮询；
- 后端不缓存预览数据；
- 每次查询成功任务时，后端都会从文件服务器读取并解析完整结果 Excel；
- 成功后继续轮询会产生无意义的文件下载、内存和 CPU 开销；
- 单次查询遇到网络错误或 `503` 时，继续查询原任务，不要重新上传；
- 前端可设置 11 分钟左右的 UI 等待上限，但以后端返回状态为准。

## 8. Sheet 预览渲染

`headers` 和每一行 `rows` 按下标对应，不能把第一行数据当成表头。

```tsx
function PreviewTable({
  preview,
  currency,
}: {
  preview: AdCleaningSheetPreview;
  currency: string;
}) {
  return (
    <section>
      <div>
        当前展示前 {Math.min(100, preview.totalRows)} 行，共{' '}
        {preview.totalRows.toLocaleString()} 行
      </div>

      <table>
        <thead>
          <tr>
            {preview.headers.map((header) => (
              <th key={header}>{header}</th>
            ))}
          </tr>
        </thead>
        <tbody>
          {preview.rows.map((row, rowIndex) => (
            <tr key={rowIndex}>
              {preview.headers.map((header, columnIndex) => (
                <td key={`${header}-${columnIndex}`}>
                  {formatPreviewCell(header, row[columnIndex], currency)}
                </td>
              ))}
            </tr>
          ))}
        </tbody>
      </table>
    </section>
  );
}
```

### 8.1 数值格式建议

接口返回的是可计算的原始数值，前端负责展示格式：

```ts
const percentHeaders = new Set([
  'CTR',
  'CVR',
  'ACOS',
  '活动均CTR',
  '广告组均CTR',
  '匹配类型均CTR',
  '全站均CTR',
  '全站均CVR',
  '全站均ACOS',
]);

const moneyHeaders = new Set([
  '花费',
  '7天销售额',
  'CPC',
  'CPA',
]);

export function formatPreviewCell(
  header: string,
  value: AdCleaningPreviewCell | undefined,
  currency: string,
): string {
  if (value === null || value === undefined || value === '') {
    return '—';
  }

  if (typeof value !== 'number') {
    return String(value);
  }

  if (percentHeaders.has(header)) {
    return `${(value * 100).toFixed(2)}%`;
  }

  if (moneyHeaders.has(header)) {
    return new Intl.NumberFormat('zh-CN', {
      style: 'currency',
      currency,
      maximumFractionDigits: 2,
    }).format(value);
  }

  if (header === 'ROAS') {
    return value.toFixed(2);
  }

  return new Intl.NumberFormat('zh-CN', {
    maximumFractionDigits: 4,
  }).format(value);
}
```

币种应使用 `task.stats.currency`，不要固定写成 USD。

### 8.2 清洗判定文案

统计字段与产品中文文案建议按以下关系展示：

| 字段 | 中文文案 |
| --- | --- |
| `good` | 可收割 |
| `bad` | 高风险 |
| `warn` | 待优化 |
| `watch` | 继续观察 |
| `neutral` | 表现中性 |

## 9. 下载结果文件

### 9.1 推荐方式：直接使用结果 URL

任务成功后，优先使用 `resultFileUrl` 作为下载地址：

```ts
export function openCleaningResult(task: AdCleaningTask): void {
  if (task.status !== 'SUCCESS' || !task.resultFileUrl) {
    throw new Error('清洗结果尚未生成');
  }

  window.open(task.resultFileUrl, '_blank', 'noopener,noreferrer');
}
```

原因是系统当前使用 Bearer Token 认证，普通的 `<a>` 或 `window.open(downloadPath)` 无法主动附加 `Authorization` 请求头。

跨域文件地址的 `download` 属性可能会被浏览器忽略，最终是直接下载还是在新窗口打开，以文件服务器返回的响应头为准。

### 9.2 后端下载接口

```http
GET /api/ad-cleaning/tasks/:taskId/download
Authorization: Bearer <access_token>
```

后端校验登录用户和任务归属后返回 `302`，重定向到 `resultFileUrl`。该接口更适合 Postman、移动端或可以为请求添加 Bearer Token 的客户端。

如果任务尚未成功，接口返回 `409 Conflict`。

## 10. 页面状态建议

| 页面状态 | 展示内容 | 可执行操作 |
| --- | --- | --- |
| 未上传 | 文件选择区、格式和大小提示 | 选择并上传文件 |
| 上传中 | 上传状态，禁用重复提交 | 取消本地请求 |
| 排队中 | `stage`、排队提示 | 等待 |
| 清洗中 | `progress` 进度条、`stage` | 等待，可离开页面 |
| 清洗成功 | 统计卡片、5 个 Sheet 标签页、下载按钮 | 切换预览、下载 Excel |
| 清洗失败 | `errorMessage` | 重新选择文件上传 |

刷新页面后，如果前端保存了 `taskId`，可以继续调用查询接口恢复任务状态。后端只保存任务和结果 URL，不保存上传原文件。

## 11. 错误处理

| HTTP 状态码 | 常见场景 | 前端建议 |
| --- | --- | --- |
| `400` | 未上传文件、格式错误、表头缺失、超出行列限制、混合币种 | 展示后端 `message`，要求用户修正文件 |
| `401` | Token 缺失或失效 | 跳转登录或刷新 Token |
| `404` | 任务不存在或不属于当前用户 | 提示任务不存在，不继续轮询 |
| `409` | 任务尚未完成却请求下载 | 返回任务页继续等待 |
| `413` | 文件超过上传大小限制 | 提示文件不能超过 50 MB |
| `503` | 队列已满，或结果文件暂时无法读取 | 队列满时稍后重新创建；查询失败时重试原任务 |

全局错误结构：

```json
{
  "statusCode": 400,
  "message": "上传文件格式不正确",
  "timestamp": "2026-08-21T02:30:00.000Z"
}
```

`message` 在参数校验错误时也可能是字符串数组，前端需要兼容两种形式。

## 12. 联调检查清单

- [ ] 未登录调用三个接口均返回 `401`；
- [ ] 上传 `.xlsx` 文件可以拿到 `taskId`；
- [ ] 上传时字段名使用 `file`，且没有手动设置 multipart boundary；
- [ ] `PENDING` 和 `PROCESSING` 状态下能正常展示进度；
- [ ] `SUCCESS` 后立即停止轮询；
- [ ] 成功后只展示 5 个中间 Sheet；
- [ ] 每个 Sheet 最多展示 100 行，并正确展示 `totalRows`；
- [ ] 百分比、金额、空值的格式正确；
- [ ] 下载按钮使用 `resultFileUrl`；
- [ ] `FAILED` 时展示 `errorMessage` 并允许重新上传；
- [ ] 查询接口临时返回 `503` 时不会重复创建任务；
- [ ] 刷新页面后可以使用保存的 `taskId` 恢复状态；
- [ ] 其他用户无法查询或下载该任务。

## 13. 当前版本的重要约定

1. 数据库只保存任务状态和清洗结果文件 URL，不保存原始数据、清洗明细、统计或预览数据。
2. 原始上传文件仅用于本次任务处理，处理完成后会删除本地临时文件。
3. 清洗结果 Excel 上传文件服务器后，本地结果文件会删除。
4. 成功任务的统计和前 100 行预览由后端每次实时读取结果 Excel 得到，没有缓存。
5. 前端收到第一次 `SUCCESS` 后必须停止轮询。
6. 接口不提供预览分页，完整数据通过结果 Excel 下载查看。
7. 服务进程重启时，尚未完成的任务会被标记为 `FAILED`，用户需要重新上传。
