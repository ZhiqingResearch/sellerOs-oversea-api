# 积分明细「调用方式」字段 — 前端对接（可直接交给 AI 实施）

更新：2026-09-11。积分明细新增**调用方式**字段与筛选：区分「平台使用」与「API 调用」（开放平台服务间扣费）。本文自足，无需读其他文档。

## 变更点总览

| 位置 | 变更 |
| --- | --- |
| `GET /api/membership/transactions` | 新增 query 参数 `invokeType`（筛选）；响应 `items[]` 新增 `invokeType`、`invokeTypeLabel` 两个字段 |
| `GET /api/membership/invitees/:userId/transactions` | 同上（分销邀请人查下级流水，参数与字段口径完全一致） |
| `GET /api/membership/transaction-options` | 响应新增 `invokeTypes` 数组（筛选下拉项，见下文） |

无破坏性变更：其余参数、字段、分页结构均不变。

## 1. 筛选参数

`invokeType` 为可选枚举 query 参数，两个取值：

| 值 | 含义 |
| --- | --- |
| `PLATFORM` | 平台使用（平台内功能的消费） |
| `API` | API 调用（开放平台服务间扣费产生的消费） |

不传 = 全部。可与其他筛选（`direction` / `bucket` / `type` / `source` / `ownership` / `consumeSource` / `consumerUserId` / 日期区间）任意叠加。非法值返回 400。

示例：

```
GET /api/membership/transactions?page=1&pageSize=10&direction=DEBIT&invokeType=API
Authorization: Bearer <登录 JWT>
```

## 2. 响应新增字段

`items[]` 每行新增两个字段，**所有行都有值**（存量数据默认 PLATFORM）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `invokeType` | `"PLATFORM"` \| `"API"` | 调用方式枚举值 |
| `invokeTypeLabel` | string | 中文标签：`平台使用` / `API 调用`，**直接展示，前端不要自行映射** |

响应片段示例：

```json
{
  "items": [
    {
      "id": 1658,
      "direction": "DEBIT",
      "bucket": "RECHARGE",
      "type": "CONSUME",
      "amount": "10",
      "invokeType": "API",
      "invokeTypeLabel": "API 调用",
      "consumeSource": "OWN_RECHARGE",
      "consumeSourceLabel": "个人充值积分"
    }
  ],
  "total": 3,
  "page": 1,
  "pageSize": 10,
  "totalPages": 1
}
```

（其余既有字段略，保持不变。）

## 3. 筛选下拉项（不要硬编码）

`GET /api/membership/transaction-options` 响应新增 `invokeTypes` 数组，与既有 `buckets` / `consumeSources` / `ownerships` 同结构同用法：

```json
{
  "invokeTypes": [
    { "value": "", "label": "全部" },
    { "value": "PLATFORM", "label": "平台使用" },
    { "value": "API", "label": "API 调用" }
  ]
}
```

前端渲染筛选下拉时直接消费该数组：选中项的 `value` 原样作为 `invokeType` query 参数提交；首项「全部」`value` 为空串，表示不带该参数。所有用户都会下发该数组，无需按身份裁剪。

## 4. 展示建议

- 列表新增「调用方式」列，直接渲染 `invokeTypeLabel`；或作为徽标（如 API 调用行加 tag）。
- 筛选器与其他筛选项并列，选项来自 `transaction-options.invokeTypes`。
