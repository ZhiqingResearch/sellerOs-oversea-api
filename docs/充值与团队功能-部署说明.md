# 充值功能 + 企业团队功能 — 部署说明

本次上线内容：在线收银台（Stripe 三渠道：微信 / 支付宝 / 银行卡；**目录/订单人民币计价，发起支付按 Stripe 实时汇率折美元收款**）、订单 / 收据 / 计费告警、自定义充值阶梯、企业团队（共享池 / 配额 / 成员 / 生命周期）、多级分销返利，以及配套的取消 LV4/LV5 特殊计费身份迁移。

> 本项目数据库结构一律用 `prisma db push` 同步，**不跑 migrate**（`prisma/migrations` 与本功能无关）。**务必先备份数据库。**

执行顺序一览（后文按此顺序展开）：

1. 拉代码、装依赖（`npm ci`）
2. 配置环境变量
3. 同步数据库结构（`npx prisma db push`）
4. 灌入种子数据（`npx ts-node prisma/seed.ts membership billing models`）
5. 老数据迁移：`migrate-lv4-lv5.ts` 先 `--dry-run` 再正式跑
6. 构建（`npm run build`）并启动应用
7. 配置 Stripe Dashboard webhook 与支付方法
8. 按「上线后验证」清单验收

## 2. 同步数据库结构

```bash
npx prisma generate          # 重新生成 Prisma Client（CI/构建若已含可跳过）
npx prisma db push           # 应用新表/新字段（本项目唯一 schema 同步方式，不跑 migrate）
```

本步涉及的结构变更：

- **新表**：`BillingOrder`、`BillingOrderItem`、`Receipt`、`Team`、`TeamMember`、`TeamModelConfig`、`TeamQuotaRequest`、`TeamAuditLog`、`TeamPlan`（团队套餐档）、`TeamPack`（团队充值包）、`CustomLadderTier`（自定义充值阶梯）、`RebateRule`（全局返利规则，单行 id=1）、`AiModel`（AI 模型目录，企业模型配置的可选池）。
- **`User` 新列**：`email`（收据/通知邮件投递地址）、`inviteQuota`、`subInviteAllowed`、`rebateEnabled`、`level2RebateRate`，以及订阅档相关 `subscriptionTier` / `subscriptionExpiresAt`。
- **`CreditLot` / `CreditTransaction` / `ScheduledPlan` 加 `teamId`**（团队共享池批次 / 企业池扣费留痕 / 团队续费排队，均为弱引用、不建外键）。
- **价格列全部人民币（元，`Decimal(10,2)`）**：`MembershipPlan.priceCny` + 新增 `originalPriceCny`（划线价）；`RechargePack.priceCny`；`TeamPlan.priceCny` + `originalPriceCny`；`TeamPack.priceCny`；`CustomLadderTier.minCny`（阶梯门槛，元）；`Team.contractAmountCny`（平台定制合同金额留痕）。

- **`HistoryType` 枚举加 `ADMIN_ACTION`**（后台敏感操作审计，如查看用户手机号全号）。

**2026-08-26 增量**：`BillingOrder.stripePaymentIntentId` 新增索引（支付回跳反查）；**删除 `TeamQuotaRequest` 表**（提额申请链路下线，dev2 上仅 1 条已处理历史行）——`prisma db push` 需 `--accept-data-loss`（Docker 入口命令已带，自动处理，无需手工）。

## 3. 灌入套餐 / 充值包 / 阶梯 / 返利规则（幂等）

```bash
npx ts-node prisma/seed.ts membership billing models features
```

- `membership`：个人会员套餐 3 档（Explorer / Plus / Ultra，¥199 / ¥399 / ¥699）、个人固定充值包 3 档（¥30 / ¥100 / ¥500）。
- `billing`：团队套餐 2 档（团队版 5 席 ¥1299 / 旗舰版 15 席 ¥2999）、团队充值包 3 档（¥500 / ¥1000 / ¥5000）、自定义充值阶梯 7 档（个人 ¥100/500/1000/5000 四档 + 团队 ¥500/1000/5000 三档）、全局返利规则 `RebateRule`（单行 id=1，默认两级返利、企业池消耗计入返利、无封顶）。
- `models`：AI 模型目录（`AiModel` 表，企业「模型配置」Tab 的可选池；文本/生图/生视频三类，按 code upsert）。
- `features`：功能模块注册表（`FeatureModule` 表，公共扣费 v2 `POST /usage/deduct/v2` 的 source 校验与中文标签单一事实来源；**漏灌会导致 deduct/v2 全部 400「未注册的功能模块」**）。
- 全部 upsert / 对账写法，**可重复跑**，不会清空业务数据。

> ⚠️ **人民币价格点目前是占位值**（个人套餐 ¥199/399/699、划线价 ¥269/539/899，团队 ¥1299/2999、划线价 ¥1665/4284 等，见 `prisma/seed/membership.ts`、`prisma/seed/billing.ts` 顶部注释）。**产品的正式定价通知后必须重灌**：改这两个 seed 文件里的 `MEMBERSHIP_PLANS` / `RECHARGE_PACKS` / `TEAM_PLANS` / `TEAM_PACKS` / `CUSTOM_LADDER_TIERS` 常量，再跑一遍上面的命令即可（幂等覆盖）；也可以直接改库。积分锚点固定 1 元 = 10 积分（`CREDIT_PER_CNY` 常量，无环境变量）。

> 💱 **汇率**：目录/订单全部人民币计价；发起支付时后端按 **Stripe FX Quotes API**（preview：`POST /v1/fx_quotes`，请求头 `Stripe-Version: 2025-11-17.preview`，取 CNY→USD `base_rate` 市场基准、不含 FX 费——USD 直接收款 Stripe 不发生兑换）实时汇率把人民币折成美元创建 PaymentIntent 收款，汇率与折算结果快照落订单（`fxRate` / `amountUsdCents`，存的是倒数：1 USD = X CNY）。`FxService`：10 分钟内存缓存；拉取失败沿用旧缓存（stale 兜底），从未成功则支付接口抛 503「汇率服务暂不可用」。**无新环境变量**，复用 `STRIPE_SECRET_KEY`。

## 4.7 老数据修复：宽限期团队被误回收的套餐/赠送批次恢复（2026-08-29 生命周期 bug 修复，条件性）

2026-08-29 前每日清零任务不区分个人/团队批次：团队套餐/赠送批次随团队同日到期，团队一进宽限期（GRACE）批次即被系统回收，导致宽限期内续费无法完整恢复。代码修复后每日任务不再清团队批次（宽限期保留，归档时统一清零留痕）；**部署时若环境内存在 GRACE 团队，需跑一次性脚本恢复被误回收的批次**（无 GRACE 团队 dry-run 全 0，可直接跳过）：

TS_NODE_TRANSPILE_ONLY=true npx ts-node scripts/restore-grace-team-lots.ts             # 正式修复
```

- 恢复口径：GRACE 团队 + 批次仍为 `EXPIRED`/`remaining=0` + 存在团队到期后的 `system.expire` 清零流水 → `remaining` 回写、`status` 回 ACTIVE（到期日维持原值，续费恢复时由 `restoreTeam` 自动顺延到新有效期）；每批写一条 `MANUAL_ADJUST` 补偿流水（`source=script.restore-grace-lots`）。
- **幂等**：已恢复的批次重跑不再命中。

npx tsx scripts/backfill-rebate-team-id.ts
```

- 两个脚本都**幂等**，可随时重跑；顺序无依赖，但必须在代码部署（新逻辑上线）之后跑。
- ② 的识别是启发式（同秒窗口唯一匹配）；分销上线初期数据量小、准确率高，越晚跑歧义越多，建议部署后尽早执行。

## 5. 构建与启动

```bash
npm run build
npm run start:prod      # 或按该环境既有方式（Docker 部署见下）
```

### Docker / 镜像

- Dockerfile 默认 `runtime` 阶段已安装收据 PDF 渲染所需的 Chromium Headless Shell 及中文字体：

  ```dockerfile
  RUN apk add --no-cache chromium-headless-shell ca-certificates font-wqy-zenhei
  ENV PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium-headless-shell
  ```

  `PUPPETEER_EXECUTABLE_PATH` **已在镜像内置 ENV，容器部署无需再配**；裸机 / PM2 部署需自行安装 Chromium Headless Shell 并配置该变量。
  **中文字体不可省**：Headless Shell 自带的 Open Sans 不含中文字形，镜像通过 `font-wqy-zenhei`（文泉驿正黑）补齐。裸机部署同理需安装中文字体（文泉驿 / Noto Sans CJK 均可），安装后执行 `fc-cache -f`。
- 生产依赖安装会排除 dev/peer 依赖，并在同一镜像层内生成 Prisma Client、清理缓存及仅供调试/编译使用的 source map 和类型声明，不影响运行时。
- 若部署环境不需要后端邮件 PDF 附件，可构建 `runtime-no-pdf` 目标进一步移除整个浏览器系统层：

  ```bash
  docker build --target runtime-no-pdf -t ai-sourcing-api:no-pdf .
  ```

  该目标不影响入账和收据 HTML 邮件，但邮件不再携带 PDF 附件。
- 容器启动命令自动执行 `npx prisma db push --accept-data-loss --skip-generate` 再拉起应用（即第 2 步在容器启动时自动完成；`--accept-data-loss` 不会回滚 schema，见「回滚注意」）。

### 定时任务清单（随应用启动自动注册，无需额外部署）

## 6. Stripe Dashboard 配置

### 6.1 API 密钥（`STRIPE_SECRET_KEY` / `STRIPE_PUBLISHABLE_KEY`）

- 位置：**Dashboard → 开发者 → API 密钥**（直达 https://dashboard.stripe.com/apikeys ），"标准密钥"表格里上下两行：**可发布密钥**（`pk_...` → `STRIPE_PUBLISHABLE_KEY`，直接可见）和**私密密钥**（`sk_...` → `STRIPE_SECRET_KEY`，点"显示"后复制）。
- **每个账号天生两对密钥，无需创建**：正式对（`sk_live` / `pk_live`，收真钱）与测试对（`sk_test` / `pk_test`，沙箱假卡）。页面右上角"**测试模式**"拨片切换显示哪一对；两对完全隔离，测试交易不进正式数据。
- 对应关系：开发/联调/测试服务器配 `sk_test` / `pk_test`；生产配 `sk_live` / `pk_live`。代码不分模式，只读环境变量。
- 密钥疑似泄露时在同一页面"滚动"（roll）换新，旧 key 有 12 小时宽限期，不会瞬间打断线上。

### 6.2 Webhook（`STRIPE_WEBHOOK_SECRET`）

- 位置：**Dashboard → 开发者 → Webhook**（https://dashboard.stripe.com/webhooks ）→ 添加端点。
- 端点 URL：`https://<API域名>/api/billing/webhooks/stripe`（全局前缀 `/api` + 控制器路由，免 JWT；必须 HTTPS 且公网可达）。
- **监听事件（勾这三个，其余事件后端只 ACK 不处理）**：

  | 事件 | 后端动作 |
  | --- | --- |
  | `payment_intent.succeeded` | **入账唯一事实源**（金额不符 → 告警不自动入账） |
  | `payment_intent.canceled` | 订单置 CANCELLED |
  | `charge.dispute.created` | 拒付告警转人工 |

- 创建后点进端点详情，"签名密钥"（`whsec_...`）配到 `STRIPE_WEBHOOK_SECRET`。
- **多端点/多环境配法**：一个账号可建多个端点，每个端点**独立的 whsec**，且端点按测试/正式模式分开（只触发对应模式的数据）。标准三层：
  1. **本地开发**：不在 Dashboard 建端点，跑 `stripe listen --forward-to localhost:8000/api/billing/webhooks/stripe`，CLI 打印的临时 `whsec_...` 配进本地 `.env`（每次 listen 重新生成）；
  2. **测试服务器**：**打开测试模式**建端点指向 `https://<dev域名>/api/billing/webhooks/stripe`，其 whsec 配到测试环境；
  3. **生产**：**关掉测试模式**建端点指向 `https://<生产域名>/api/billing/webhooks/stripe`，其 whsec 配到生产环境。
  三个端点可同时存在，Stripe 会把同一事件群发给所有订阅端点，但测试单只触发测试模式端点，不会串到生产。每个部署环境只认自己 `.env` 里那一个 `STRIPE_WEBHOOK_SECRET`，验签对不上即拒收。
- 验证：端点详情页"发送测试事件"发一个 `payment_intent.succeeded`，服务日志可见接收记录；验签失败返回 400，Dashboard 的投递记录里能看到。
- ⚠️ **不要动 `src/main.ts` 的 body parser 配置**：webhook 验签依赖原始请求体，`app.useBodyParser("json", { verify })` 里已把 buf 挂到 `req.rawBody`，改动解析顺序或去掉 verify 回调会导致验签失败。

### 6.3 支付方法

- **微信支付（`wechat_pay`）与支付宝（`alipay`）需要境外（如美国）主体，并在 Dashboard → 支付方法里启用**；后端按 `payment_method_types: ["wechat_pay"] / ["alipay"]` 创建 PaymentIntent，未启用会报错。
- **银行卡（`card`）默认启用**，无需额外操作。
- 微信渠道返回 `image_data_url` 二维码（15 分钟有效）；支付宝渠道返回收银台跳转地址，`returnUrl` 由前端下单时传入；银行卡渠道返回 `clientSecret` 供前端 Elements 即时确认。

## 7. 上线后验证

### 7.1 冒烟：未带 token 应全部 401

```bash
for p in \
  /api/billing/catalog \
  /api/team \
  /api/admin/teams \
  /api/admin/subscriptions \
  /api/admin/dist/rebate-rules \
  /api/users/1/phone ; do
  curl -s -o /dev/null -w "%{http_code} $p\n" "https://<API域名>$p"
done
```

预期每行都是 `401`（这些接口均挂 `JwtAuthGuard`；`/api/admin/*` 与 `/api/users/:id/phone` 还挂权限守卫，带普通用户 token 应 403）。

### 7.2 带有效 JWT 验证商品目录

```bash
curl -H "Authorization: Bearer <JWT>" \
  https://<API域名>/api/billing/catalog
```

预期返回目录 JSON，顶层字段为 `creditPerCny`（固定 10）、`plans`（个人套餐 3 档）、`packs`（个人充值包 3 档）、`customLadder`（个人阶梯 4 档）、`teamPlans`（团队套餐 2 档）、`teamPacks`（团队充值包 3 档）、`teamCustomLadder`（团队阶梯 3 档），价格（人民币元）/ 到账积分 / 单价 / 折扣标签均由后端算好下发。**数量不对先回查第 3 步种子是否跑过。**

### 7.3 支付链路（测试密钥下）

- 用 `sk_test_...` 下一笔小额银行卡测试单（Stripe 测试卡 `4242 4242 4242 4242`），Dashboard 触发 / 等待 `payment_intent.succeeded` webhook 到账：订单 → PAID/SETTLED，`CreditTransaction` 出现入账流水，收据邮件送达（配了 `PUPPETEER_EXECUTABLE_PATH` 时经 DirectMail Advance 带 PDF 附件；附件失败会自动降级纯 HTML 并打告警日志）。**附件通道已在美东 endpoint 实测通过**；换区域/换账号部署时可用 `npx ts-node scripts/test-mail-attachment.ts <邮箱>` 一条命令复验。
- 故意改单测试告警：金额不符 / 拒付场景应收到 `BILLING_ALERT_EMAIL` 告警邮件且**不自动入账**。

## 8. 回滚注意

- **`prisma db push --accept-data-loss` 不回滚 schema**：代码回滚后，新表 / 新列留在库里不影响旧代码运行（旧代码不读这些表）；如需彻底回退库结构，只能从步骤 0 的备份恢复。
- **LV4/LV5 迁移不可逆**：等级列已被重算覆盖；如需恢复个别用户，按 `scripts/data/lv4-lv5-backup-<时间戳>.json` 备份人工改回。
- **续费排队单迁移（§4.5）不可逆**：积分批次/充值流水已到账、有效期已顺延；代码回滚到排队制后新续费会重新排队，但已激活的批次不会自动收回，需人工按 `source=migrate.renewal` 的流水核对处理。
- Stripe webhook 在 Dashboard 删除对应端点即可摘除；订单 / 收据数据留在 `BillingOrder` / `Receipt` 表中不受应用回滚影响。
