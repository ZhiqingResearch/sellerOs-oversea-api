# 手机验证码登录前端联调文档

Seller 登录页新增「验证码登录」方式：发送短信验证码，再使用手机号和验证码换取 `access_token`。登录成功后复用现有的 token 保存、用户信息获取与页面跳转逻辑。

更新日期：2026-10-09。后端已启用短信登录接口，前端需连接部署了本次改动的服务进行联调。UAT 是否可用以部署结果为准；仅合入 UAT 分支不代表服务已经更新。

## 接口与环境

| 方法 | 路径 | 用途 | 认证 |
| --- | --- | --- | --- |
| POST | `/api/auth/send-code` | 发送登录验证码 | 无需 token |
| POST | `/api/auth/login-sms` | 手机验证码登录 | 无需 token |
| GET | `/api/auth/me` | 登录后获取用户、角色、组织、权限 | Bearer token |

请求体使用 JSON，设置 `Content-Type: application/json`。成功响应直接返回对象，没有 `data` 包装层。

- 本地后端默认地址：`http://127.0.0.1:8000`，需启动后端服务。
- 项目现有 UAT API 地址：`https://uat-api.intelligentselleros.com`，短信接口需在本次代码部署完成后联调。
- Swagger 路径：`/api-docs`。
- 前端若通过 BFF 或代理转发，需要接通上述两个 POST 路由；基础地址已包含 `/api` 时，不要重复拼接。

## 发送验证码

```http
POST /api/auth/send-code
Content-Type: application/json
```

```json
{
  "phone": "13800138000"
}
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| phone | string | 是 | 中国大陆手机号，按字符串传入 |

示例手机号仅用于说明格式，联调时替换为自己的测试号码。

成功返回 **HTTP 201**：

```json
{
  "message": "验证码已发送"
}
```

发送成功后启动 60 秒倒计时。后端没有返回验证码、有效期或剩余倒计时字段；前端按 60 秒展示重发按钮，验证码有效期为 5 分钟。发送按钮在请求期间应禁用，避免重复点击；只有成功后才提示「验证码已发送」。

发送接口不校验账号是否已注册或是否停用，账号状态在验证码登录时校验。短信发送成功不代表账号可以登录，也不会自动注册账号。

## 验证码登录

```http
POST /api/auth/login-sms
Content-Type: application/json
```

```json
{
  "phone": "13800138000",
  "code": "123456"
}
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| phone | string | 是 | 中国大陆手机号，与接收短信的手机号一致 |
| code | string | 是 | 6 位数字，保留前导零，例如 `"012345"` |

成功返回 **HTTP 201**：

```json
{
  "access_token": "<JWT token>"
}
```

手机号验证码登录和密码登录返回同样的 token 结构。前端只在获得 `access_token` 后进入已登录流程，不要将发送短信成功视为登录成功。

登录后调用现有用户信息接口：

```http
GET /api/auth/me
Authorization: Bearer <access_token>
```

返回 `{ user, roles, orgs, permissions }`。按现有登录逻辑处理 `user.mustChangePassword` 等字段；详细字段见 [用户信息接口联调文档](auth-me邮箱注册标识-前端联调文档.md)。

## 错误响应与页面提示

业务错误与参数校验错误返回 **HTTP 400**，统一结构为：

```json
{
  "statusCode": 400,
  "message": "审核中，请联系平台顾问",
  "timestamp": "2026-10-09T06:30:00.000Z"
}
```

`message` 可能是字符串，也可能是参数校验产生的字符串数组。数组可用 `message.join("；")` 展示。登录页应展示接口返回的提示，不要统一覆盖成「登录失败」，也不要对这些 400 错误触发会话失效跳转。受保护接口的 token 失效仍按现有 401 流程处理。

| 接口 | message | 前端处理 |
| --- | --- | --- |
| 两个接口 | `请输入有效的手机号` | 提示用户修正手机号 |
| 验证码登录 | `验证码必须为6位数字` | 提示用户修正验证码格式 |
| 发送验证码 | `验证码获取过于频繁，请60秒后再试` | 提示稍后重发；响应不含精确剩余秒数 |
| 发送验证码 | `短信服务未配置，请联系管理员` | 展示提示，需后端检查配置 |
| 发送验证码 | `短信发送失败，请稍后再试` | 展示提示，不进入登录流程 |
| 验证码登录 | `验证码无效或已过期` | 可重新输入或重新获取验证码 |
| 验证码登录 | `审核中，请联系平台顾问` | 展示审核提示，不保存 token、不跳转到已登录页面 |
| 验证码登录 | `用户不存在` | 展示提示，引导走现有注册入口 |
| 验证码登录 | `账号已停用，请联系管理员` | 展示提示，不进入已登录页面 |

必填或类型校验也可能返回其他 DTO 提示，前端按 `message` 通用展示即可。

## 验证码使用规则

- 每条验证码有效期 5 分钟，仅最新一条可用；重发会作废旧码。
- 同一验证码只能成功核销一次，重复提交返回「验证码无效或已过期」。
- 当前有效码累计输入错误 5 次后不可再使用，需要重新获取。后端不返回剩余错误次数。
- 验证码先核销，再检查账号状态。因此待审核、账号不存在或停用时，正确验证码也会被核销；再次尝试需重新获取。
- 手机号改变时清空已输入的验证码。倒计时需与发送时的手机号关联，避免切换号码后混用状态。
- 不要自动重试发送或登录请求。网络超时后可能已发送短信或已核销验证码，应提示用户检查短信或重新获取。
- 短信发送失败也会留下发送记录并作废新码，同手机号仍受 60 秒发送间隔限制。

## 前端请求示例

以下示例按前端 `/api` 代理方式编写，需先配置对应路由的转发；直接调用后端时，将路径前加上后端域名。

```ts
type ApiError = { message?: string | string[] }

async function postAuth<T>(path: string, body: object): Promise<T> {
  const response = await fetch(`/api/auth/${path}`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(body),
  })
  const data = await response.json()
  if (!response.ok) {
    const message = (data as ApiError).message
    throw new Error(
      Array.isArray(message) ? message.join("；") : message || "请求失败，请稍后再试"
    )
  }
  return data as T
}

export function sendLoginCode(phone: string) {
  return postAuth<{ message: string }>("send-code", { phone: phone.trim() })
}

export function loginWithSms(phone: string, code: string) {
  return postAuth<{ access_token: string }>("login-sms", {
    phone: phone.trim(),
    code: code.trim(),
  })
}
```

页面捕获请求错误并展示提示；登录成功后，把 `access_token` 交给现有登录成功处理函数。验证码输入框使用文本类型配合 `inputMode="numeric"`，避免数字类型丢失前导零。手机号、验证码都按字符串保存。

## 联调验收

| 场景 | 预期 |
| --- | --- |
| 正常账号获取验证码并登录 | 发送 201；登录 201 并返回 token；调用 `/api/auth/me` 成功 |
| 同手机号 60 秒内重发 | 返回 400，提示发送过于频繁 |
| 非法手机号或非 6 位数字验证码 | 返回 400，不调用发送或登录业务 |
| 错误、过期、已使用或旧验证码 | 返回 400，提示验证码无效或已过期 |
| 同一有效码输入错误 5 次后再输入正确码 | 仍返回 400，需要重新获取 |
| 待审核用户输入正确验证码 | 返回 400，提示「审核中，请联系平台顾问」 |
| 停用用户输入正确验证码 | 返回 400，提示账号已停用 |
| 未注册手机号输入正确验证码 | 返回 400，提示用户不存在，不自动创建账号 |

本地已验证真实短信发送及接收、登录 token 签名、发送限频、错误码和重复核销拦截，39 项相关测试、ESLint 与生产构建通过。测试手机号尾号 `3673` 的验证码已核销，前端联调需重新获取。

## 后端部署条件

后端需设置 `ACCESS_KEY_ID`、`ACCESS_KEY_SECRET`、`SMS_SIGN_NAME`、`SMS_TEMPLATE_CODE`，短信模板变量名为 `${code}`。这些配置只放后端，前端无需配置阿里云密钥。

本次新增 `SmsCode.attempts` 字段。当前配置的开发数据库已完成该字段同步，其他环境部署时也需要通过项目规定的 `prisma db push` 同步 schema 并生成 Prisma Client。数据库若包含其他分支表结构，先核对差异，避免删除无关表或字段。部署后再启动或重启后端进行 UAT 联调。
