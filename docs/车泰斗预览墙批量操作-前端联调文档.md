# 车泰斗预览墙批量操作：前端联调文档

日期：2026-10-06

## 接入范围

新增车泰斗预览墙的批量下载、批量删除接口。前端按钮 icon、样式、多选形式、选中数量、确认弹窗和反馈方式，复用通用创作预览墙现有实现。后端不新增按钮或控件配置，也不修改 `GET /api/chetaidou/config`。

两个接口均要求 `Authorization: Bearer <token>`，以及车泰斗权限 `tool.ai_creative_studio.chetaidou`。用户身份从登录态获取，前端不传 `userId` 或业务类型。

图片 ID 必须使用 `GET /api/chetaidou/skus/:skuId/results` 返回的数字 `resultId`；不是任务 ID、母版 ID、通用创作的 `imageId` 或前端卡片 key。

## 接口一：批量下载

```http
POST /api/chetaidou/skus/:skuId/results/batch-download
Authorization: Bearer <token>
Content-Type: application/json
```

请求示例：

```json
{
  "resultIds": [101, 102]
}
```

参数规则：

| 参数 | 类型 | 规则 |
|---|---|---|
| `skuId` | 路径整数 | 当前预览墙所属 SKU |
| `resultIds` | `number[]` | 必填、非空、不重复的正整数；不能传数字字符串 |

允许选择当前 SKU 下不同生成批次的图片，返回顺序与传入 ID 顺序一致。后端未新增批量数量上限。全部图片必须属于当前用户、当前 SKU 和车泰斗业务，并且未删除、`status=SUCCEEDED`、已经交付文件。任意一张不满足条件，则整批报错，不返回部分下载清单。

成功响应：HTTP 200。

```json
{
  "count": 2,
  "expiresAt": "2026-10-06T08:10:00.000Z",
  "items": [
    {
      "resultId": 101,
      "url": "https://<存储域名>/<私有对象路径>?<签名参数>",
      "filename": "CS1plus_NO7_12345678_1.png",
      "expiresAt": "2026-10-06T08:10:00.000Z"
    },
    {
      "resultId": 102,
      "url": "https://<存储域名>/<私有对象路径>?<签名参数>",
      "filename": "CS1plus_NO7_87654321_2.jpg",
      "expiresAt": "2026-10-06T08:10:00.000Z"
    }
  ]
}
```

这是 JSON 下载清单，接口不返回 ZIP 或二进制图片。链接有效期为 10 分钟，返回 UTC ISO 时间。文件扩展名按实际 MIME 提供，前端不要统一改为 `.png`。

前端接到清单后，沿用通用创作的文件下载或 ZIP 打包流程，以 `filename` 保存图片。签名链接过期时重新调用此接口获取；本地网络、CORS 或下载失败不代表后端生成失败，不要发起生图重试。

## 接口二：批量删除

```http
POST /api/chetaidou/skus/:skuId/results/batch-delete
Authorization: Bearer <token>
Content-Type: application/json
```

请求体与批量下载相同：

```json
{
  "resultIds": [101, 102]
}
```

成功响应：HTTP 200。

```json
{
  "success": true,
  "requestedCount": 2,
  "removedCount": 2,
  "alreadyRemovedCount": 0,
  "resultIds": [101, 102]
}
```

| 字段 | 含义 |
|---|---|
| `requestedCount` | 本次请求的图片数量 |
| `removedCount` | 本次新删除的图片数量 |
| `alreadyRemovedCount` | 请求中此前已删除的数量 |
| `resultIds` | 已确认处于删除状态的全部请求 ID，保持请求顺序 |

删除规则：

- 仅能删除本人在当前 SKU 的车泰斗生成结果。
- `SUCCEEDED`、`FAILED`、`CANCELLED` 可以删除；若仍有未终结的模型调用，后端会拒绝并返回 `RESULT_NOT_REMOVABLE`。
- `QUEUED`、`RUNNING`、`SETTLING`、`DELIVERY_PENDING`、`UNKNOWN` 不可删除。删除接口不会取消任务。
- 整批事务执行，任意未删除项不允许删除时全部失败，不会先删其他图片。
- 重复删除同一批有效 ID 返回成功，`removedCount=0`、`alreadyRemovedCount=请求数量`，不要求提供 `idempotencyKey`。
- 软删除只移出预览墙，不退款、不立即删除存储文件，也不删除母版、任务、调用账本或扣费记录。
- 已删除结果不能再下载或重试。此前签发的链接在其原有效期内仍可能可用。

确认弹窗建议文案：

> 确定删除选中的 N 张图片？删除后将从预览墙移除，已产生的费用不会退回。

前端可按通用创作的现有弹窗排版呈现这段含义。

## 已有接口的变化

### 预览墙

`GET /api/chetaidou/skus/:skuId/results?page=1&pageSize=20` 会自动排除已删除图片，`total` 和分页按剩余结果计算。响应字段保持兼容，前端无需额外过滤列表接口的数据。

### 任务详情及产物

`GET /api/chetaidou/tasks/:taskId` 和 `GET /api/chetaidou/tasks/:taskId/output` 保留历史图片席位，每项新增 `deletedAt`，未删除时为 `null`。

```json
{
  "resultId": 101,
  "index": 1,
  "status": "SUCCEEDED",
  "deletedAt": "2026-10-06T08:00:00.000Z",
  "url": null
}
```

任务历史保留原始状态、数量、成功/失败进度及生成规格。`deletedAt` 非空时图片已从预览墙删除，前端不能从任务历史重新补回该卡片，也不能提供下载或重试入口。任务整体状态、扣费记录不会随预览墙删除改变。

### 单张下载和重试

- 已删除图片调用 `GET /api/chetaidou/results/:resultId/download` 返回 404。
- 显式将已删除 ID 传给 `POST /api/chetaidou/tasks/:taskId/retry` 返回 400，`code=RESULT_REMOVED`。
- 不传 `resultIds` 的失败图重试自动跳过已删除的失败图片；没有剩余失败图片时沿用原有「没有可重试的失败图片」错误。
- 若删除与重试同时发生，以事务认领结果为准，冲突的一方返回 409，请刷新后重试。

## 错误响应与前端处理

统一异常结构：

```json
{
  "statusCode": 409,
  "code": "RESULT_NOT_REMOVABLE",
  "message": "生成中、交付中或待核对的图片不可删除，请等待处理完成",
  "timestamp": "2026-10-06T08:00:00.000Z"
}
```

| HTTP | code | 含义及处理 |
|---|---|---|
| 400 | 无固定 code | DTO 校验失败：ID 数组为空、重复、非正整数等；`message` 可能是中文数组 |
| 400 | `RESULT_IDS_INVALID` | 服务层 ID 校验失败，修正选择后重试 |
| 400 | `RESULT_NOT_DOWNLOADABLE` | 含未成功或未交付的图片，重新选择 |
| 404 | `RESULT_NOT_FOUND` | ID 不存在、归属其他用户、其他 SKU 或通用创作；下载时已删除也使用此码，刷新列表 |
| 409 | `RESULT_NOT_REMOVABLE` | 存在生成中、交付中、待核对的图片或调用，等待完成并刷新 |
| 409 | `RESULT_STATE_CHANGED` | 删除执行期间图片状态变化，刷新后重试 |
| 400 | `RESULT_REMOVED` | 重试接口收到已删除的图片，移除选择并刷新 |
| 401 / 403 | 沿用现有鉴权响应 | 登录失效或无车泰斗权限 |

单张下载、现有重试的其他错误保持原有契约，不保证带新增 code。

## 前端交互清单

1. 在预览墙复用通用创作的批量工具栏、按钮 icon 和图片勾选交互，不新增一套交互样式。
2. 多选值使用数字 `resultId`；显示选中数量。切换 SKU 时清空选择；跨页选择是否保留按通用创作现有行为处理，两个接口支持同 SKU 跨页、跨批次 ID。
3. 批量下载仅允许成功且有 URL 的图片。批量删除仅允许成功、失败、已取消项；模型调用是否已终结仍以接口校验为准。
4. 无选择时禁用操作。下载清单请求期间禁用重复提交；删除从确认弹窗确认到请求结束期间禁用重复操作。
5. 删除成功后移除响应 `resultIds` 的本地选择，重新请求预览墙。若当前页删空或超出剩余最大页，回到有效页重新加载。
6. 操作失败显示后端 `message`；400/404/409 不模拟部分成功，涉及状态变化时刷新列表。
7. 任务轮询继续保持原有流程。预览墙由结果列表恢复；若前端也从任务详情拼接卡片，必须过滤 `deletedAt` 非空的席位。
8. 下载接口只负责签名清单，文件下载进度和失败反馈沿用通用创作；部署域名下验证图片存储的 CORS 和文件名保存。

## 联调验收

- 同 SKU 的不同生图批次可一起下载，清单顺序与选择 ID 一致，PNG/JPEG/WebP 的扩展名正确。
- 删除成功图片、失败图片、已取消图片后刷新页面，它们不再出现在预览墙，总数和分页正确。
- 重复删除返回成功及正确的已删除计数，不修改任务或扣费记录。
- 选择中混入运行中、交付中或待核对图片时整批删除失败，其他卡片保留。
- 同时发起删除和失败图重试时，不会恢复已删除结果；失败的一方提示刷新。
- 跨用户、跨 SKU、通用创作或不存在的 ID 整批拒绝，不返回他人的下载链接。
- 已删除项的单张、批量下载被拒绝；任务历史仍显示原始进度，删除项无图片 URL。
- 签名链接过期后重新获取清单即可下载，不触发生图或重复扣费。

## 后端部署说明

本次使用通用 `ImageGenItem.deletedAt` 可空时间列，按 `ImageGenItem.id`（预览墙 `resultId`）批量软删除。当前由车泰斗删除入口写入；展示、下载和重试显式过滤删除项。共享执行/结算仍读取完整席位，不将此模型加入全局软删除过滤，保留任务进度和费用账本的完整性。

目标环境需先同步 Schema，再发布代码。默认按仓库规范执行：

```bash
npm run db:push
npx prisma generate
npm run build
```

按本次要求，也提供 SQL 上线交付：

- 已上线车泰斗、尚未新增该字段的环境：执行一次 [新增字段 SQL](../scripts/sql/2026-10-06-chetaidou-preview-wall-batch-delete.sql)，仅添加 `deletedAt`，无需旧字段改名或数据迁移。执行后核验 `datetime(3)`、允许 NULL、默认 NULL。
- 首次上线车泰斗的环境：[上线结构 SQL](../prisma/chetaidou-2026-09-28.sql) 已在 `ImageGenItem` 扩展语句中包含该列，不需要额外执行增量。此文件包含既有建表和索引语句，不用于对已上线环境整份重复执行。
- SQL 同步该列后，仍需 `npx prisma generate` 和 `npm run build`；不要运行 `prisma migrate deploy`。

实际新增字段的 DDL：

```sql
ALTER TABLE `ImageGenItem`
    ADD COLUMN `deletedAt` DATETIME(3) NULL DEFAULT NULL
    COMMENT '软删除时间，NULL表示未删除';
```

无需回填存量数据，旧行该列为 `null`。这份实现已在本地生成 Prisma Client；未对目标数据库执行 `db:push` 或 SQL。前端正式联调前确认目标库已同步该列，避免查询不存在列。
