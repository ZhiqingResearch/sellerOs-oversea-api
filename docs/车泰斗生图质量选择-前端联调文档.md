# 车泰斗生图质量选择——前端联调文档

更新日期：2026-10-07。适用于部署本次后端版本后的车泰斗工作台。

生图开放顶层 `quality` 参数：`standard`（标准）、`hd`（高清）。当前模型 `gpt-image-2.5-sunburst` 的网关实时 Schema 已核实支持这两个值。质量与 `resolutionTier`（1K/2K/4K 尺寸档位）独立，可以同时选择。

本次修改后端接口并提供前端接入契约；前端页面需按本文接入。无需新增环境变量、修改数据库或运行 `db:push`。请求继续携带 `Authorization: Bearer <JWT>`，要求 `tool.ai_creative_studio.chetaidou` 权限。

## 1. 前端控件

在原“比例 / 尺寸 / 张数”生成区增加“质量”：

| 展示文案 | 提交值 |
| --- | --- |
| 标准 | `standard` |
| 高清 | `hd` |

建议新页面默认选中“标准”，提交时明确传 `quality: "standard"`。后端没有强制默认标准：旧客户端省略 `quality` 时仍不指定模型质量，由网关采用默认行为；不要把“省略”当成已明确选择标准。

质量选择只在创建 GENERATE 时提交，可保存在当前母版的浏览器本地状态。更改质量不修改服务端草稿，不使已有 READY 组合过期，也不要求重新联想或组合。原 `GET /api/chetaidou/config` 不增加质量控件配置，前端维护以上两个选项。

## 2. 创建生图任务

```http
POST /api/chetaidou/tasks
Authorization: Bearer <JWT>
Content-Type: application/json
```

新增字段：

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `quality` | string | 否 | 仅 `standard` / `hd`；只用于 `type=GENERATE` |

后端会去掉首尾空白并转小写，`" HD "` 与 `"hd"` 等价。前端统一发送小写枚举。空字符串、null、非字符串，以及 `auto` / `high` / `low` 均返回 400；需要沿用模型默认时直接省略字段。

其他字段沿用[比例与尺寸联调文档](车泰斗生图比例尺寸-前端联调文档.md)：新建任务必传实际 `aspectRatio`，`count` 为 1/2/4/8，`compositionTaskId` 为当前已成功且 READY 的 COMPOSE 根任务 UUID。

高清示例：

```json
{
  "type": "GENERATE",
  "imageId": 19,
  "compositionTaskId": "61c3a1a8-4ac5-4f7c-84f6-f524ea57bb24",
  "idempotencyKey": "cc92b568-57f3-4f47-8e11-4a1ea64a9fbf",
  "draftRevision": 6,
  "count": 2,
  "aspectRatio": "16:9",
  "resolutionTier": "2K",
  "quality": "hd"
}
```

标准质量仅将 `quality` 改为 `standard`；用户主动生成另一批图片时同时生成新的 `idempotencyKey`。

首次创建成功返回 HTTP 202：

```json
{
  "taskId": "a7c301d4-88e4-4a13-8d8b-e22d977a49ae",
  "imageGenJobId": "69242dc8-89b2-4e83-a96f-53eacfbf4061",
  "status": "QUEUED",
  "items": [
    { "resultId": 310, "index": 1, "status": "QUEUED" },
    { "resultId": 311, "index": 2, "status": "QUEUED" }
  ]
}
```

网络重发必须保留原键和原请求，包括质量。原键同参复用原任务；重放响应沿用现有任务详情结构，使用 `response.taskId ?? response.id` 获取任务 ID。同键改变质量返回 409 `IDEMPOTENCY_CONFLICT`，不会再创建一批图片。省略质量与显式 `standard` 也属于不同请求。

## 3. 查询和展示

以下接口的 `generation` 返回已冻结的质量：

- `GET /api/chetaidou/tasks/:id`：生图任务详情。
- `GET /api/chetaidou/tasks`：生图任务列表。
- `GET /api/chetaidou/skus/:skuId/results`：预览墙每项的 `generation`。

任务详情节选：

```json
{
  "id": "a7c301d4-88e4-4a13-8d8b-e22d977a49ae",
  "type": "GENERATE",
  "generation": {
    "model": "gpt-image-2.5-sunburst",
    "count": 2,
    "quality": "hd",
    "aspectRatio": "16:9",
    "resolutionTier": "2K",
    "providerApplied": { "aspect_ratio": "16:9", "resolution": "2k" }
  }
}
```

此示例仅列相关字段，其余现有返回字段保持原契约。`quality` 在 `generation.quality`，不是 `providerApplied.quality` 或单项 `generationMeta.quality`。模型实际生成和重试使用该冻结值；尺寸适配不会把 hd 自动改成 standard。

结果卡片可显示“高清 · 2K · 16:9”，同时保留现有实际宽高和尺寸适配提示。卡片读取该批次 `generation.quality`，不能读取当前下拉框选择，以免历史图片随控件变化。

`GET /api/chetaidou/tasks/status?ids=...` 仍用于轻量状态轮询，不新增质量字段；需要完整参数时请求详情或刷新预览墙。`GET /api/chetaidou/tasks/:id/output` 仍以 items 为主，整体规格读取详情。

历史任务、旧客户端省略质量的任务可能没有 `generation.quality`，甚至没有 `generation`；展示“模型默认 / 历史未记录”或隐藏标签，不推断为标准。历史冻结值 `high` 可在展示时兼容为“高清”，新请求只发送 `hd`。

## 4. 失败重试与重新生成

失败图沿用原接口：

```http
POST /api/chetaidou/tasks/a7c301d4-88e4-4a13-8d8b-e22d977a49ae/retry
```

```json
{
  "idempotencyKey": "517b77bb-1c79-432c-babb-87651d6c21f4",
  "resultIds": [310]
}
```

仅重试 FAILED 项，保留原 resultId/index、组合、质量、比例、尺寸及模型。重试接口不接受质量修改；不要附带当前下拉框值。要把标准改成高清，使用当前 READY 组合新建 GENERATE，并换新幂等键。原模型已停用时沿用现有拒绝重试行为。

## 5. 错误与计费

响应沿用 `{ statusCode, code?, message, details?, timestamp }`。DTO 校验的 message 可能为字符串数组，且不一定有 code。

| 情况 | HTTP / code | 前端处理 |
| --- | --- | --- |
| 非法质量枚举、空值、非字符串 | 400；业务校验可带 `IMAGE_GENERATION_PARAM_INVALID` | 提示选择标准或高清 |
| 非 GENERATE 携带 quality | 400 / `IMAGE_GENERATION_PARAM_INVALID` | 只在生图请求中组装该字段 |
| 当前模型 Schema 不接受所选质量 | 400 / `IMAGE_GENERATION_PARAM_INVALID` | 提示改选质量；后端不静默降级 |
| 同键更改质量 | 409 / `IDEMPOTENCY_CONFLICT` | 新一轮生成换新 UUID；网络重发保留原参数 |
| 模型缺失、Schema 无效等 | 503 / `MODEL_NOT_READY` | 提示模型未就绪，联系管理员 |
| 创建时模型配置发生变化 | 409 / `MODEL_CONFIG_CHANGED` | 提示用户重新提交 |

计费继续沿用现有规则：模型配置一口价时按张收取；否则按实际网关账单与模型倍率结算。前端不要根据 hd 自行硬编码加价或翻倍。

## 6. 联调验收

| 场景 | 预期 |
| --- | --- |
| 标准 / 高清分别生成 | 请求正确传枚举，详情与预览墙保留对应质量 |
| 高清配 1K/2K/4K | 质量和尺寸分别保存；尺寸适配提示仍正常 |
| 改质量后使用原 READY 组合生成 | 无需重新组合；创建另一批时换新键 |
| 网络超时后原键重发 | 复用原任务，不重复创建 |
| 同键换质量 | 409；新批次未创建 |
| 高清任务失败后，将控件切到标准再重试 | 重试仍使用原高清质量 |
| 旧请求省略 quality | 仍可创建；不强制指定标准或高清 |
| 非法值 / null / 非 GENERATE 携带质量 | 400，不创建生图批次 |
| 历史记录缺少质量 | 页面无报错，不伪造质量标签 |

本次后端验证覆盖参数校验、幂等、Task/Job 冻结、网关提交、预览墙及失败重试。真实付费生图和前端页面显示需在部署后联调验收。
