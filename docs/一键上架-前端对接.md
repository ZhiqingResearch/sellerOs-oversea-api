# 一键上架 / 上架记录—前端 API 对接文档

> 本文档可直接交给前端实现型 AI。接口统一前缀为 `/api/product-publish`，全部业务接口使用 Bearer JWT。

## 1. 前端需要完成的功能

1. 加载可用 Amazon 店铺、每个店铺的分类及永久模板 URL。
2. 创建、自动保存、打开一键上架草稿。
3. 生成 Excel，通过预签名 URL 直传 Spaces，再完成任务。
4. 将 Excel 公开 HTTPS URL 提交给后端上架。
5. 任务进入 `PUBLISHING` 后显示“上架中”，不允许重新上架。
6. 建立 SSE 事件连接；点击“刷新结果”后保持 loading，收到对应刷新完成事件后停止 loading 并重新拉取任务。
7. 在上架记录中展示 Amazon 批次 ID、成功/失败数、结果文件及 SKU-ASIN 映射。

RPA 是后端内部实现。前端不得直接请求影刀，也不得保存影刀密钥、任务 ID 或应用 ID。

## 2. 通用约定

### 2.1 请求头

```http
Authorization: Bearer <JWT>
Content-Type: application/json
```

Spaces 预签名上传 URL 除外：不拼 API Base URL，不带 JWT，请求体直接传 `Blob`/`File`，并完整使用后端返回的上传请求头。

### 2.2 错误格式

```ts
interface ApiError {
  statusCode: number
  message: string | string[]
  timestamp: string
}
```

`409` 表示任务状态冲突，常见于重复上架、上架中修改/删除任务。收到 `409` 后应立即重新拉取任务，不要自动重试提交上架。

### 2.3 分页

```ts
interface PageResult<T> {
  total: number
  page: number
  pageSize: number
  items: T[]
}
```

`page` 默认 `1`，`pageSize` 默认 `10`、最大 `100`。

## 3. TypeScript 数据结构

```ts
type ProductPublishStatus = "DRAFT" | "PUBLISHING" | "COMPLETED"
type ProductPublishType = "SINGLE" | "VARIANT"
type TemplateStatus = "PENDING" | "SUCCESS" | "FAILED"
type PublishOutcome = "SUCCESS" | "PARTIAL_SUCCESS" | "FAILED" | "TIMEOUT"

interface StoreCategory {
  id: number
  classification: string // 大写字母、数字和单个空格；下划线已替换为空格
  classificationName: string
  sortOrder: number
  templateUrl: string | null
  templateStatus: TemplateStatus
  templateSyncedAt: string | null
}

interface ProductPublishStore {
  id: number // 后端内部 ID，前端不传这个值
  externalStoreId: string // 业务店铺 ID，提交时映射到 storeId
  name: string
  shortName: string | null
  companyName: string | null
  platform: "AMAZON"
  accountType: string | null
  categories: StoreCategory[]
}

interface ProductPublishImage {
  id?: string
  originalUrl: string
  washedUrl?: string
  washStatus?: "PENDING" | "SUCCESS" | "FAILED"
  errorMessage?: string
}

interface SkuAsinItem {
  sku: string
  asin: string | null
  status: "SUCCESS" | "FAILED"
  error_code?: string
  error_message?: string
}

interface ProductPublishRefreshCompletedEvent {
  taskId: string
  requestId: string
  callbackOk: boolean
  amazonStatus: "ACCEPTED" | "PROCESSING" | "SUCCESS" | "PARTIAL_SUCCESS" | "FAILED" | null
  taskStatus: "PUBLISHING" | "COMPLETED"
  publishOutcome: PublishOutcome | null
  receivedAt: string
}

interface ProductPublishTask {
  id: number
  taskId: string
  imageProjectId: number | null // 可选；准备和完成上架 Excel 时不要求关联图片项目
  productName: string | null
  brand: string | null
  classification: string | null
  category: string | null
  data: Record<string, unknown> | null
  status: ProductPublishStatus
  store: string | null
  publishStoreId: number | null
  publishStore: Omit<ProductPublishStore, "id" | "categories"> | null
  type: ProductPublishType | null
  productImages: ProductPublishImage[] | null
  progress: number
  spreadsheetUrl: string | null
  spreadsheetKey: string | null

  uploadId: string | null
  rpaTaskUuid: string | null
  rpaJobUuidList: string[] | null
  submitRequestId: string | null
  resultRequestId: string | null
  successCount: number
  failedCount: number
  submittedFileUrl: string | null
  resultFileUrl: string | null
  skus: string[] | null
  skuAsinMapping: SkuAsinItem[] | null
  publishOutcome: PublishOutcome | null
  publishSubmittedAt: string | null
  publishCompletedAt: string | null
  lastPolledAt: string | null
  nextPollAt: string | null
  pollAttempts: number
  publishErrorMessage: string | null

  completedAt: string | null
  createdAt: string
  updatedAt: string
  classificationInfo: {
    code: string
    name: string
    templateFilename: string | null
    templateUrl: string | null
    templateStatus?: TemplateStatus
    templateSyncedAt?: string | null
  } | null
}

interface TaskSummary extends Omit<ProductPublishTask, "data" | "productImages"> {
  previewImageUrl: string | null
}
```

`externalStoreId`/`storeId` 一律按字符串保存和传输，不要转成 JavaScript `number`，否则长 ID 会丢失精度。

`uploadId` 是 RPA 调用 Amazon 服务后由 Amazon 生成的业务批次 ID，不是影刀 `taskUuid` 或 `jobUuidList`。

## 5. 店铺和模板

### `GET /api/product-publish/stores`

```json
[
  {
    "id": 9,
    "externalStoreId": "27826971599669",
    "name": "Amazon US",
    "shortName": "美区店",
    "companyName": "示例公司",
    "platform": "AMAZON",
    "accountType": "主账号",
    "categories": [
      {
        "id": 101,
        "classification": "HEADPHONES",
        "classificationName": "Headphones",
        "sortOrder": 1,
        "templateUrl": "https://files.example.com/templates/headphones.xlsm",
        "templateStatus": "SUCCESS",
        "templateSyncedAt": "2026-08-03T03:10:00.000Z"
      }
    ]
  }
]
```

页面规则：

- 只展示选中店铺的 `categories`。
- 任务中传 `storeId=externalStoreId`，不传内部 `id`。
- `templateStatus !== "SUCCESS"` 或 `templateUrl === null` 时禁止生成 Excel，并提示模板尚未就绪。
- 模板 URL 永久有效、可公开访问，可直接下载。

## 6. 草稿与 Excel

### 6.1 创建草稿

`POST /api/product-publish/tasks`

```json
{
  "imageProjectId": 123,
  "productName": "Bluetooth Headphones",
  "brand": "Demo",
  "storeId": "27826971599669",
  "classification": "HEADPHONES",
  "category": "Electronics > Headphones",
  "type": "SINGLE",
  "progress": 20,
  "data": { "version": 1 },
  "productImages": [
    { "id": "main", "originalUrl": "https://images.example.com/1.jpg" }
  ]
}
```

返回完整 `ProductPublishTask`。后续路由与接口使用响应中的 UUID `taskId`，不使用数字 `id`。

### 6.2 增量保存

`PATCH /api/product-publish/tasks/:taskId`

请求体与创建入参一致，只传本次改动字段。`PUBLISHING` 任务返回 `409`。

### 6.3 草稿查询

- `GET /api/product-publish/tasks/draft-count` → `{ "count": 3 }`
- `GET /api/product-publish/tasks/drafts?page=1&pageSize=10` → `PageResult<TaskSummary>`
- `GET /api/product-publish/tasks/:taskId` → `ProductPublishTask`

### 6.4 洗图片链接

`POST /api/product-publish/tasks/:taskId/wash-image-links`

```json
{ "imageUrls": ["https://images.example.com/1.jpg"] }
```

将响应中的成功/失败结果合并回 `productImages`。不要在前端请求第三方图床。

### 6.5 上传并完成 Excel

1. 请求上传地址：

```http
POST /api/product-publish/tasks/:taskId/spreadsheet-upload-url
```

```json
{ "filename": "amazon-listing.xlsm" }
```

2. 按响应中的 `uploadUrl` 和 `headers` 直传文件。
3. 直传成功后调用：

```http
POST /api/product-publish/tasks/:taskId/complete
```

```json
{ "spreadsheetKey": "<预签名接口返回的 key>" }
```

响应中 `status="COMPLETED"`、`progress=100`，并返回 `spreadsheetUrl`。

## 7. 提交上架

### `POST /api/product-publish/tasks/:taskId/publish`

```json
{
  "fileUrl": "https://files.example.com/product-publish/amazon-listing.xlsm",
  "skus": ["SKU-001", "SKU-002"]
}
```

前置条件：

- 任务已完成 Excel，当前为 `COMPLETED`。
- 已绑定未禁用的 Amazon 店铺。
- `fileUrl` 是当前任务完成接口已保存的 `spreadsheetUrl`（允许同一对象附带签名 query），且 RPA 可通过 HTTPS 直接下载；不得传其他任务或任意外部文件。
- `skus` 是本次 Excel 中的完整 SKU 字符串列表，至少 1 项、最多 100000 项；每项去除首尾空格后不能为空、最长 200 字符，且不能重复。
- 该任务从未提交过上架。

返回核心字段：

```ts
interface PublishResponse {
  success: true
  accepted: true
  requestId: string
  message: string
  task: ProductPublishTask
}
```

后端会在首次提交时规范化并冻结 `skus`，之后不允许修改。完成一次影刀 `upload_listing` 启动尝试后立即异步返回。`accepted=true` 只表示后端已受理并永久锁定本次上架请求；通常影刀已确认接收，但网络超时或连接重置时也可能表示“影刀接收结果未知、继续等待可能到达的回调”，绝不表示 Amazon 已接收文件。以响应 `message` 和后续任务状态为准，不得因结果未知而重新提交。等待回调期间，数据库状态仍为 `COMPLETED`，但 `submitRequestId` 已非空，因此任务已永久锁定、不能重新提交或修改；`task.uploadId` 仍为 `null`。

RPA 执行完成后会将 Amazon 生成的 `upload_id` 异步提交给后端。后端保存 `uploadId` 的同时把任务更新为 `PUBLISHING`。前端通过任务详情或记录列表获取最新状态，不得把 `requestId`、`rpaTaskUuid` 或 `rpaJobUuidList` 当作 Amazon 批次 ID。

不论首次提交是否超时或返回不明，前端都不得再次调用此接口。重复请求返回 `409`。请展示 `publishErrorMessage`并交由运维根据 RPA 日志排查。

## 8. 刷新处理结果

### 8.1 建立 SSE 事件连接

```http
GET /api/product-publish/events
Accept: text/event-stream
Authorization: Bearer <JWT>
```

该连接按 JWT 用户隔离。连接成功后先收到 `connected`，空闲期间每 20 秒收到 `heartbeat`。RPA 的 `check_feed_status` 回调成功落库后，后端发送：

```text
id: <本次刷新接口返回的 requestId>
event: product-publish-refresh-completed
data: {"taskId":"...","requestId":"...","callbackOk":true,"amazonStatus":"PROCESSING","taskStatus":"PUBLISHING","publishOutcome":null,"receivedAt":"2026-08-04T08:00:00.000Z"}
```

注意：原生浏览器 `EventSource` 不能设置 `Authorization` 请求头。本项目使用 Bearer JWT，前端应使用支持请求头的 SSE 客户端，例如 `@microsoft/fetch-event-source`，不得把 JWT 放进 URL 查询参数。

页面进入时建立一个 SSE 连接，页面离开时通过 `AbortController.abort()` 关闭。不要每点一次刷新就永久新增一条连接。

### 8.2 主动刷新

### `POST /api/product-publish/tasks/:taskId/publish/refresh`

无请求体。只允许查询已有 `uploadId` 的 `PUBLISHING` 任务。接口会异步返回后端已受理本次查询启动尝试；影刀接收结果可能已确认，也可能因网络异常暂时未知，接口不会等待 Amazon 处理结果。

后端主动调起 `check_feed_status` 脚本，并将任务中冻结的 `skus` 与 Amazon `uploadId` 一起发送给 RPA。RPA 取得 Amazon 结果后再异步提交给后端。前端在收到 `accepted=true` 后保存响应中的 `requestId` 并保持 loading；收到 `taskId`、`requestId` 均匹配的 `product-publish-refresh-completed` 事件后停止 loading，再调用任务详情或记录接口获取最新完整结果。

`callbackOk=false` 表示 RPA 本次查询失败，但该次回调已经处理完成，前端同样必须停止 loading、重新拉取详情并展示 `publishErrorMessage`。`amazonStatus=ACCEPTED/PROCESSING` 表示本次查询成功但 Amazon 尚未处理完，任务仍是 `PUBLISHING`。

前端实现必须处理快速回调竞态：SSE 事件可能先于刷新 POST 响应到达。建议临时缓存最近事件，拿到 POST 的 `requestId` 后再匹配一次：

```ts
import { fetchEventSource } from "@microsoft/fetch-event-source"

const pendingRefresh = new Map<string, string>() // taskId -> requestId
const recentEvents = new Map<string, ProductPublishRefreshCompletedEvent>()
const controller = new AbortController()

void fetchEventSource(`${apiBase}/api/product-publish/events`, {
  headers: { Authorization: `Bearer ${token}` },
  signal: controller.signal,
  openWhenHidden: true,
  onmessage(message) {
    if (message.event !== "product-publish-refresh-completed") return
    const event = JSON.parse(message.data) as ProductPublishRefreshCompletedEvent
    recentEvents.set(event.requestId, event)
    if (pendingRefresh.get(event.taskId) !== event.requestId) return

    pendingRefresh.delete(event.taskId)
    setRefreshing(event.taskId, false)
    void reloadTask(event.taskId)
  },
})

async function refreshPublishResult(taskId: string) {
  setRefreshing(taskId, true)
  try {
    const response = await api.post(`/product-publish/tasks/${taskId}/publish/refresh`)
    pendingRefresh.set(taskId, response.data.requestId)
    const earlyEvent = recentEvents.get(response.data.requestId)
    if (earlyEvent) {
      pendingRefresh.delete(taskId)
      setRefreshing(taskId, false)
      await reloadTask(taskId)
    }
  } catch (error) {
    setRefreshing(taskId, false)
    throw error
  }
}
```

处理中：

- `status="PUBLISHING"`
- `publishOutcome=null`
- 持续展示后端返回的成功/失败数。

终态：

- `status="COMPLETED"`
- `publishOutcome` 为 `SUCCESS` / `PARTIAL_SUCCESS` / `FAILED` / `TIMEOUT`
- 展示 `resultFileUrl`、`skuAsinMapping`、`publishCompletedAt`。

后端还会每 5 分钟自动查询所有到期的 `PUBLISHING` 任务，定时查询的结果也会通过同一 SSE 通道发送。前端只用刷新接口返回的 `requestId` 停止对应按钮的 loading。SSE 断线或超时情况下，保留每 30–60 秒查询 `GET /tasks/:taskId` 的降级方案；不要每几秒重复触发 `publish/refresh`。

## 9. 上架记录

### `GET /api/product-publish/records`

参数：

```ts
interface RecordsQuery {
  page?: number
  pageSize?: number
  keyword?: string
  status?: ProductPublishStatus
  store?: string
  storeId?: string
  classification?: string
  category?: string
  type?: ProductPublishType
}
```

响应为 `PageResult<TaskSummary>`。列表至少展示：

- 商品名、品牌、店铺、分类、类型和状态；
- `uploadId`、`successCount`、`failedCount`、`publishOutcome`；
- `submittedFileUrl`、`resultFileUrl`；
- 原始 `skus` 以及处理结果 `skuAsinMapping`；
- `publishSubmittedAt`、`publishCompletedAt`、`publishErrorMessage`。

`skuAsinMapping` 建议在详情抽屉中用表格展示，失败项同时展示 `error_code` 和 `error_message`。

### `DELETE /api/product-publish/records/:taskId`

软删除当前用户的记录。`PUBLISHING` 或 `submitRequestId` 已非空的任务返回 `409`，前端需禁用删除按钮。

## 10. 建议页面状态机

```text
DRAFT
  → 生成/上传 Excel
COMPLETED (Excel 已完成、尚未提交)
  → POST /publish，仅一次
COMPLETED + submitRequestId (启动尝试已受理，等待 upload_id 回调，不可重提)
  → RPA 回传 Amazon upload_id
PUBLISHING
  → 后端自动查询或用户主动刷新
COMPLETED + publishOutcome
```

注意：`COMPLETED` 同时用于“Excel 已完成”和“Amazon 已到终态”。前端使用 `publishOutcome` 和 `submitRequestId` 区分：

- `COMPLETED && submitRequestId === null`：可提交上架。
- `COMPLETED && submitRequestId !== null && publishOutcome === null`：启动尝试已受理、等待 `upload_id` 回调；页面显示“提交中”，不可重新提交或修改。
- `PUBLISHING`：上架中，仅允许查看和刷新。
- `COMPLETED && submitRequestId !== null && publishOutcome !== null`：已提交过且已结束，不论结果如何都不得重新上架。

## 11. 对接验收清单

- [ ] 店铺 ID 全程使用字符串。
- [ ] 分类只来自当前店铺 `categories`。
- [ ] 模板未就绪时不生成 Excel。
- [ ] 预签名上传不带 JWT，不使用 FormData。
- [ ] `/publish` 仅允许用户点击一次，不自动重试。
- [ ] `PUBLISHING` 时禁用修改、重新完成、洗链和删除。
- [ ] 主动刷新调用 `/publish/refresh`，不重新提交文件。
- [ ] `uploadId` 标注为 Amazon 业务 ID，不展示成 RPA 任务 ID。
- [ ] 上架记录完整展示新增字段和失败原因。
